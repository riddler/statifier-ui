# Session subscriber and trace normalizer implementation plan

## Overview

Build the plumbing every inspector pane consumes: write `docs/wire-format.md`
- the normative specification ADR-0005 assigns to the bead that builds the
first producer - and then build that producer. A pure normalizer turns
`Statifier.Effect` values into wire-shaped messages, a manifest builder turns
a compiled `%Statifier.Machine{}` into the `session.start` definition message,
a bounded buffer keeps a chatty machine from growing a notebook without limit,
and a `GenServer` owns the process concern: attach, detach, `seq` stamping,
and session death.

Every module lands under `lib/statifier_ui/trace/` and references neither
`Kino` nor `Phoenix.LiveView` - this is the layer `.claude/wurk/codebase.md`
describes as "the layer a non-Elixir interpreter could target".

Beads issue: `sui-t36.3` (parent `sui-t36`, the Livebook inspector; blocked-by
`sui-w1b` and `sui-t36.1`, both closed; blocks `sui-t36.5` and `sui-t36.7`).

## Current State Analysis

`lib/statifier_ui/` holds five core modules, all from sui-t36.2: `Fixtures`,
`Fixtures.Source`, `Fixtures.Sidecar`, `Value`, and `Shape`. There is no
`lib/statifier_ui/trace/` directory, no `docs/wire-format.md`, and nothing in
the repository has ever touched a `Statifier.Session`. `mix quality` is green
on this branch's base commit (`941c1c0`).

What is already decided and must be honored:

- **ADR-0005** fixes the envelope (`type`, `session`, `seq`, the three
  counters on `trace.*`, identities never resolved nodes), the nine `trace.*`
  type names, the `session.start` definition message and its contents, the
  `$`-tagged JSON discipline, the integer `version` starting at `1`, the
  must-ignore-unknown rule, and - the clause this bead executes - that the
  normative spec lives at `docs/wire-format.md` and is "written by the
  implementation bead that builds the first producer".
- **ADR-0002 / ADR-0010 / `CLAUDE.md`**: the engine is not modified from here.
  The spike (`docs/research/260816-sui-t36.1-trace-coverage-spike.md`) filed
  eight `st-` beads; this plan consumes the engine exactly as it stands today
  and works around each gap on the consumer side, recording the workaround
  rather than reaching for a patch.
- **ADR-0004 / "The dependency rule"**: every module here is core. No `Kino`,
  no `Phoenix.LiveView`, no `jason`.
- **ADR-0003**: the `fixtures` field on `session.start` carries the sidecar's
  JSON object verbatim, `version` included.

What the engine actually provides, verified against the vendored dependency:

- **An effect is always `{tag, payload_struct}`** -
  `deps/statifier/lib/statifier/effect.ex:11-20,113-138`. Nine `{:trace, _}`
  payloads and nine core tags (`:log`, `:done`, `:budget_exhausted`,
  `:invoke`, `:cancel_invoke`, `:autoforward`, `:send`, `:send_delayed`,
  `:cancel`). `trace?/1` at `:146-148` is the single-match discriminator.
- **All nine trace payloads enforce `macrostep`/`microstep`/`round`**
  (`deps/statifier/lib/statifier/effect/trace/*.ex`). Full field inventory:
  `EventDequeued{event, from}`, `TransitionsSelected{t_indexes, event}`,
  `ExitSet{indexes}`, `EntrySet{indexes}`, `ContentExecuted{owner,
  c_indexes}`, `MacrostepStable{configuration}`, `Done{donedata,
  configuration}`, `InvokePass{state_indexes, invoke_ids}`,
  `FinalizeAutoforward{event, finalized, forwarded}`.
- **No core effect carries `round`** except `BudgetExhausted`
  (`deps/statifier/lib/statifier/effect/log.ex:23`,
  `invoke.ex:46`, `send.ex:48`, `cancel.ex:20`, and the rest). This is GAP 1 /
  `st-nbmj`, unfixed upstream.
- **The subscriber envelope** is
  `{:statifier, session_id, message}`, defined once at
  `deps/statifier/lib/statifier/session.ex:1250-1255`, with `message` being
  `{:effect, effect}`, `{:halted, :done | :cancelled | :budget_exhausted}`,
  or the (currently unreachable) `{:unroutable, effect}`.
- **The session monitors its subscribers; nothing monitors the session for
  them.** `init/1` (`session.ex:494-497`) and `handle_call({:subscribe, ...})`
  (`:633-642`) each `Process.monitor` the subscriber, and a dead subscriber is
  dropped on its own `:DOWN` (`:715-726`). A subscriber that wants to know the
  session died must monitor it itself. Halting does not stop the process
  either (`session.ex:45-57`), so `{:halted, _}` is not a process death.
- **`start_link/2` runs `initialize/2` to quiescence before returning**, so a
  pid added by `subscribe/2` afterwards has already missed the opening
  `EntrySet` / `ContentExecuted` / `InvokePass` / `MacrostepStable`. Passing
  `:subscribers` at start is the only way to see it (GAP 6 / `st-uqo4`).
- **`start_link/2` accepts `:session_id`** (`session.ex:326-353`), which is
  what makes a byte-comparable golden trace possible in a test.
- **`%Statifier.Machine{}` does not retain the SCXML source text.**
  `machine.ex:113-161` has `states`, `id_to_index` (partial, string id ->
  index), `transitions`, `contents`, `data_elements`, `name`, `datamodel`,
  `binding`, `location`, `global_scripts`, `warnings` - and no document
  source. `Statifier.Parser.parse/1`
  (`deps/statifier/lib/statifier/parser.ex:91`) takes the binary and never
  hands it back. ADR-0005 wants the chart source on `session.start`, so the
  **host must supply it**; it cannot be recovered from the Machine.
- **There is no `index_to_id` map.** `id_to_index` is partial (only states
  with a non-nil id, `machine.ex:29`). The state table is built by walking
  `machine.states`, which is a tuple of `%Machine.State{}` in document order.
- **Locations are full spans** with byte offsets:
  `%Statifier.Parser.Location{start_line, start_column, start_offset,
  end_line, end_column, end_offset}`
  (`deps/statifier/lib/statifier/parser/location.ex:13-37`).
  `%Machine.State{}` and `%Machine.Transition{}` both carry `location`, and
  `Transition` additionally carries `cond_location`
  (`machine/transition.ex:55-78`).
- **One content node kind does not carry `:location`.**
  `Statifier.Machine.Content.Script` has `:node_location` instead
  (`machine/content/script.ex:48`); `Raise`, `Log`, `Assign`, `If`, `Foreach`,
  `Send`, and `Cancel` all carry `:location`
  (`machine/content/{raise,log,assign,if,foreach,send,cancel}.ex`). A manifest
  builder that assumes `:location` on every content node crashes on the first
  `<script>`.
- **`Event.Cause.origin/0` has eight variants**
  (`deps/statifier/lib/statifier/event/cause.ex:133-141`) and
  `Content.owner/0` has four (`machine/content.ex:64-68`), plus
  `ContentExecuted` widens `owner` with `{:global_script, index}`
  (`effect/trace/content_executed.ex:54`). Every one is an Elixir tuple and
  none of them may cross the wire as one.
- **`MapSet`s cross the wire as arrays.** `configuration` is
  `MapSet.t(non_neg_integer())` on `MacrostepStable`, `Trace.Done`, and
  `BudgetExhausted`.

What already exists here to build on:

- **`StatifierUI.Value.encode/1`** (`lib/statifier_ui/value.ex:124`) is the
  ADR-0005 `$`-tagged encoder, producing JSON-ready terms rather than a JSON
  string. It is currently wired to no writer - the codec's moduledoc says it
  exists "so the codec is round-trip testable". This bead is its first caller.
  It handles `:undefined`, `%Date{}`, `%DateTime{}`, duration maps (via
  `Shape.duration?/1`), lists, and host maps; a scalar it does not recognize
  falls through unchanged (`value.ex:151`). **Atoms, tuples, `MapSet`s, and
  unknown structs are outside its domain** - a tuple passes through opaquely
  and an unknown struct is walked as a map. Everything this bead hands it must
  therefore already be reduced to the predicator value domain.
- **`StatifierUI.Fixtures.diagnostic/0`** (`fixtures.ex:49-54`):
  `%{kind: atom(), message: String.t(), path: [String.t()], source: Path.t() |
  nil}` - the established shape for a non-fatal finding, reused here.
- **Error style**: every error is `{:error, {tag, ...context}}`, atom-tagged,
  never raised at a leaf. `Logger.warning/1` is used only for diagnostics, and
  only in `Sidecar`.
- **Gate**: `warnings_as_errors`, strict Credo, Dialyzer, Doctor at 100%
  moduledoc / 75% doc+spec, 80% coverage floor. Tests are
  `async: true`, `describe` blocks named `"fun/arity - category"`.

## Desired End State

`docs/wire-format.md` exists and is normative, and six modules under
`lib/statifier_ui/trace/` implement it, such that:

1. A host compiles a chart, starts `StatifierUI.Trace.Subscriber`, passes its
   pid to `Statifier.Session.start_link(machine, trace: true, subscribers:
   [sub])`, and reads back an ordered list of `%StatifierUI.Trace.Message{}`
   beginning with `session.start` at `seq: 0`.
2. `StatifierUI.Trace.Json.encode_to_string/1` renders any message as
   canonical JSON - object keys lexicographic - so two runs of the same chart
   with the same pinned `session_id` produce byte-identical JSON Lines.
3. The normalizer is pure: `Normalizer.normalize(effect, ctx)` needs no
   process, and the whole type vocabulary is testable from a struct literal.
4. Nothing under `lib/` names `Kino` or `Phoenix.LiveView`, and `mix.exs`
   gains no dependency.
5. A drift test asserts the set of `type` strings documented in
   `docs/wire-format.md` equals `Normalizer.types/0`, so spec and code cannot
   diverge silently.
6. A golden-trace test runs a real session over a heredoc chart with a pinned
   `session_id` and compares the emitted JSON Lines byte-for-byte against a
   checked-in fixture - the conformance mechanism ADR-0005 names.

### Key Discoveries

- `deps/statifier/lib/statifier/effect.ex:11-20` - every effect is
  `{tag, payload}`, so the normalizer's top-level dispatch is a tuple match
  and the "is this a trace effect" question is `Effect.trace?/1`.
- `deps/statifier/lib/statifier/session.ex:1250-1255` - the one definition
  site of the message envelope this bead consumes.
- `deps/statifier/lib/statifier/machine.ex:113-161` - **no SCXML source on the
  Machine**. This is the single most consequential discovery for
  `session.start`: the chart source is a host-supplied input, not a derived
  one.
- `deps/statifier/lib/statifier/machine/content/script.ex:48` - `:node_location`
  where every sibling has `:location`.
- `deps/statifier/lib/statifier/session.ex:326-353` - `:session_id` is a
  start option, which is what makes golden traces deterministic.
- `docs/research/260816-sui-t36.1-trace-coverage-spike.md` GAP 4 /
  `st-r6l9` - trace effects can arrive **after** `{:halted, :done}`. A
  subscriber that treats `:halted` as end-of-stream drops the tail. This is
  the sharpest lifecycle constraint on phase 5.
- `docs/research/260816-sui-t36.1-trace-coverage-spike.md` GAP 1 / `st-nbmj` -
  core effects carry no `round`, so ADR-0005's counter clause is satisfiable
  for `trace.*` only. The spec must say so rather than invent a value.
- `lib/statifier_ui/value.ex:124-151` - `encode/1` is a passthrough for terms
  outside the predicator value domain, which means an atom, a tuple, or a
  `MapSet` reaching it produces silent garbage rather than an error. Every
  such term must be reduced by the normalizer before `Value.encode/1` is
  called.

## What We're NOT Doing

- **No Kino widget, no rendering, no panes.** `sui-t36.4`/`.5`/`.6`/`.7`/`.8`
  own those. This bead ships the data they read.
- **No datamodel on the wire.** GAP 2 / `st-oef3` means nothing on the effect
  stream reports a datamodel change, and polling `Session.snapshot/1` from
  inside the subscriber would race the session and be unreproducible under
  replay. The spec **reserves** the type name `session.datamodel` and states
  that it is not yet emitted; `sui-t36.7` (the explorer, which wants a live
  datamodel per macrostep) owns its own polling policy against
  `Session.snapshot/1` until `st-oef3` lands. Reserving without emitting is
  deliberate: it keeps the name from being claimed by something else and
  records the gap in the normative document where a second interpreter will
  look for it.
- **No following of invoke children.** GAP 3 / `st-fd7n` means a parent's
  subscriber cannot discover a child session's pid, and inheritance of
  `:trace`/`:subscribers` is an open upstream design call (spike Open question
  2). One subscriber watches one session. `session.start` still carries the
  origin fields (`parent_session`, `invokeid`) when a caller supplies them, so
  the format is ready for a tree the moment the engine is.
- **No transport and no carrier.** ADR-0005 explicitly leaves transport out.
  There is no LiveView push, no Kino frame, no file writer here - listeners
  receive Elixir messages and `Trace.Json` renders bytes on request.
- **No decoder.** The wire format's Elixir side is a producer this milestone.
  A consumer that reads JSON back into `%Message{}` values has no caller yet;
  `Value.decode/1` already covers the value half if one ever appears.
- **No `Sidecar` reading in the subscriber.** `session.start`'s `fixtures`
  field takes an already-decoded JSON object from the caller. Making the
  subscriber load files would put IO in a `GenServer` that must never block.
- **No replay integration.** `Statifier.Replay` produces a better-ordered
  stream than live delivery today (spike Open question 4), and a time-travel
  pane is phase 3 of the research doc's phasing. The normalizer is pure and
  takes effects, so a replay-driven producer is a later caller, not a change.
- **No backpressure or subscription filtering.** ADR-0005 names both as
  carrier concerns. The bounded buffer is memory safety, not flow control.
- **No engine patch for any of the eight `st-` gaps.** ADR-0002 and ADR-0010
  put those beads in statifier-ex. Each workaround below names the bead it
  waits on.

## Implementation Approach

Six phases, split on module boundaries. Phase 1 is the specification, written
first because ADR-0005 makes it normative - "when the spec and an
implementation disagree, the spec is what conformance means" - and a spec
written after the producer documents an accident rather than a decision.
Phases 2 through 4 are pure modules with no process; phase 5 is the only
`GenServer`; phase 6 syncs the prose.

**Module layout** (all core - referencing neither optional integration):

```
docs/wire-format.md                       the normative spec        (phase 1)
lib/statifier_ui/trace/message.ex         StatifierUI.Trace.Message    (phase 2)
lib/statifier_ui/trace/json.ex            StatifierUI.Trace.Json       (phase 2)
lib/statifier_ui/trace/normalizer.ex      StatifierUI.Trace.Normalizer (phase 2)
lib/statifier_ui/trace/manifest.ex        StatifierUI.Trace.Manifest   (phase 3)
lib/statifier_ui/trace/buffer.ex          StatifierUI.Trace.Buffer     (phase 4)
lib/statifier_ui/trace/subscriber.ex      StatifierUI.Trace.Subscriber (phase 5)
```

`trace/` rather than a flat `lib/statifier_ui/`: `.claude/wurk/codebase.md`
names it as the intended home for "the language-neutral wire format and the
code that turns statifier trace effects into it", and unlike the fixtures
modules (which had no natural directory) this bead is exactly that layer.

### Nine design decisions this plan settles

Each of these is something ADR-0005 delegated to the spec document or that the
engine's actual shape forced. They are recorded here so review does not
re-litigate them, and each is restated in `docs/wire-format.md` where a second
interpreter will read it.

**1. One envelope struct with a string-keyed payload map, not a struct per
type.** `%StatifierUI.Trace.Message{type, session, seq, macrostep, microstep,
round, payload}` where `payload` is a `%{String.t() => json_term()}` map
already in wire shape. Nineteen payload structs would be nineteen field lists
that have to stay in lockstep with the spec by hand; one envelope keeps the
spec as the single definition site of what a payload contains, and the bead's
own wording - "in-process structs here, but field-for-field the documented
JSON shapes" - is satisfied by a struct whose payload *is* the documented
shape. Panes match on `type` and read `payload["..."]`. The cost is that
Dialyzer cannot check a payload's keys; the drift test and the golden trace
are what cover that instead.

**2. `effect.*` is the namespace for the core (non-trace) effects.** ADR-0005
says non-trace families "get their own namespaces as consumers need them" and
sketches `log`, `done`, `budget_exhausted`, and the send/invoke family. A
top-level `done` type would sit confusingly beside `trace.done`, which is a
different message about the same moment. So the nine core tags map one-to-one
onto `effect.log`, `effect.done`, `effect.budget_exhausted`, `effect.invoke`,
`effect.cancel_invoke`, `effect.autoforward`, `effect.send`,
`effect.send_delayed`, and `effect.cancel`. Two visibly distinct halves:
`trace.*` are Appendix D phase boundaries with all three counters, `effect.*`
are the core vocabulary with two. Recorded as an open question below, since it
is a reading of ADR-0005 rather than a quotation of it.

**3. `round` is absent from `effect.*` messages, never inferred.** GAP 1 /
`st-nbmj`. ADR-0005 puts the three counters on every `trace.*` message and the
engine delivers exactly that; borrowing a neighbouring effect's `round` would
be a consumer-side guess baked into the wire, and the spike says why it breaks
(two rounds emitting into one batch). The spec states the omission, names the
bead, and says the key becomes required when the bead lands - which is
additive, not a version bump, under ADR-0005's versioning rule.

**4. Exit and entry sets keep the engine's emission order; only genuinely
unordered sets are sorted.** ADR-0005's JSON discipline says "set-valued
fields (configurations, exit/entry sets) serialize as arrays in a canonical
order (ascending index)". Taken literally that destroys information: the spike
records exit order as inner-to-outer and entry order as entry order, and the
event-log pane (`sui-t36.5`) renders exactly that sequence. The purpose of the
canonical-order rule is byte-comparability, and the engine's exit/entry order
is deterministic for a given run, so preserving it costs nothing the rule was
protecting. The resolution: `trace.exit_set` and `trace.entry_set` `indexes`
are **sequences in emission order**; `configuration` on
`trace.macrostep_stable`, `trace.done`, and `effect.budget_exhausted` is a
genuine `MapSet` and **is** sorted ascending; object keys are lexicographic
everywhere. Flagged below as an open question, because it is the one place
this plan reads ADR-0005 against its literal words.

**5. Absence is how "no value" is spelled, everywhere - not only for
`_event.data`.** ADR-0005 fixes key-absence vs JSON `null` for `_event.data`.
This plan generalizes it to every nullable engine field: `Event`'s
`invokeid`/`origin`/`origintype`/`sendid`/`cause`, `Log`'s `label`/`c_index`/
`owner`, `Trace.Done`'s `donedata`, and - the load-bearing case -
`TransitionsSelected`'s `event`, whose `nil` marks an eventless (NULL) round.
A consumer reads the absence of `"event"` on `trace.transitions_selected` as
"this was the eventless selection". The alternative (an explicit
`"eventless": true` flag) adds a field whose only content is the absence of
another one. `_event.data` keeps its three-way rule unchanged: absent means
`:undefined`, JSON `null` means `nil`, `{}` means empty map.

**6. Elixir tuples become tagged objects with a `"kind"` discriminator.**
Nothing tuple-shaped crosses the wire. The eight `Event.Cause.origin/0`
variants and the five `owner` variants (four from `Content.owner/0` plus
`{:global_script, index}`) each become a JSON object whose `"kind"` is the
tag's name and whose remaining keys are the tag's positional fields named:
`{:content, c, owner}` -> `{"kind": "content", "c_index": c, "owner": {...}}`,
`{:onentry, s, o}` -> `{"kind": "onentry", "state_index": s, "ordinal": o}`,
and so on. `"kind"` rather than `"$kind"`: the `$`-prefixed one-key shape is
reserved by ADR-0005 for the value codec, and these are multi-key structural
objects in a known position, not values in a value slot.

**7. `session.start` takes the chart source and the fixtures from the caller.**
The Machine does not retain SCXML text (see Key Discoveries), so the `source`
key is present only when the host passes one and absent otherwise - which is
exactly ADR-0005's absence discipline. Same for `fixtures`: the caller hands
over the sidecar's decoded JSON object verbatim, `version` field included, and
absence means the host supplied none. The location tables are built from the
`%Machine{}` alone, giving element-level spans plus `cond_location` on
transitions, but **not** attribute-level granularity, because
`attribute_locations` lives on the Document layer (ADR-0007's Consequences;
`sui-qay`). The spec says which layer its table came from, which is precisely
the caveat the spike left for whoever drafts it.

**8. The bounded buffer drops oldest, and `seq` gaps are the drop record.**
An inspector wants the recent tail, not the first thousand messages of a
livelocked chart. Because every message carries a per-session monotonic `seq`
starting at `0`, a consumer detects loss by reading the first buffered
message's `seq` - no separate drop notification, no synthetic message that
would itself consume a `seq` and corrupt the very counter it reports on. The
buffer also exposes `dropped/1` for a status line. Default capacity 1000: a
busy macrostep is tens of effects, so a thousand holds a few hundred steps and
bounds a notebook at low single-digit megabytes.

**9. The subscriber never calls into the session, and never treats `:halted`
as end-of-stream.** No `GenServer.call` from the subscriber into the session
it is subscribed to: the session runs `initialize/2` inside `init/1`, so a
call issued while the caller's own `start_link` chain is unwound can block on
a process that is blocked (the shape behind GAP 5 / `st-xbaz`), and it would
make the producer's output depend on when it asked rather than on what it was
sent. Everything the subscriber emits is derived from messages it received.
The session id therefore arrives from the first `{:statifier, session_id, _}`
message rather than from `Session.session_id/1`, and the manifest is emitted
at that moment as `seq: 0`, before the triggering message is normalized as
`seq: 1`. And `{:halted, reason}` produces a `session.halted` message and
changes nothing else, because GAP 4 / `st-r6l9` proves trace effects arrive
after it.

### Before phase 1: two readings of ADR-0005 that need sign-off first

Seven of the nine decisions above fill in something ADR-0005 explicitly
delegated to the spec document. **Two do not.** Decision 2 (`effect.*` as one
namespace) and decision 4 (exit/entry sets in emission order rather than
ascending) each read ADR-0005 against language that names the exact fields at
issue - "their own namespaces", plural, and "set-valued fields
(configurations, exit/entry sets) serialize as arrays in a canonical order
(ascending index)".

Both are defensible and the reasoning is written down, but neither is cheap to
reverse once built: decision 2 is a version bump to undo under ADR-0005's own
versioning rule, and decision 4 changes the literal bytes of the phase 5
golden fixture, so a late reversal reworks phases 1, 2, and 5 rather than
editing a paragraph.

**This is therefore a checkpoint, not a note.** Before phase 1's first line is
written, one of two things must have happened for each of the two decisions:
the user has confirmed the plan's reading, or a one-paragraph amendment to
ADR-0005 has been filed recording it. Open questions 1 and 2 below are that
checkpoint's agenda. An implementer arriving at this plan with neither done
raises it and waits; proceeding is the expensive path this section exists to
close off. Nothing else in the plan blocks on anything.

## Phase 1: The wire-format specification

### Overview

Write `docs/wire-format.md`, the document ADR-0005 names as the format's
normative home. Nothing else in this phase - the spec is the contract the next
four phases are implemented against, and writing it first is what makes
"the spec is what conformance means" true rather than decorative.

A note on the commit trigger: this phase touches no Elixir code, so
`CLAUDE.md`'s clause applies - "a change touching no Elixir code has no gate
to run and may commit on review of the diff alone". Run `mix quality` anyway;
it costs only time and it proves the tree was clean.

### Changes Required

#### 1. The specification document

**File**: `docs/wire-format.md` (new)
**Changes**: the normative spec. Structure:

- **Status and scope.** Version 1. Cites ADR-0005 as the record that settled
  the envelope and delegated field-by-field schemas here. States the
  conformance rule: producer MUST emit `session.start` and, with tracing on,
  the nine `trace.*` types; consumers MUST ignore unknown fields and unknown
  types; additive change is not a version bump.
- **The envelope.** `type`, `session`, `seq`, and - on `trace.*` only -
  `macrostep`, `microstep`, `round`. Says plainly that `effect.*` messages
  carry `macrostep` and `microstep` but not `round`, names `st-nbmj` as the
  reason, and states that adding it later is additive.
- **Ordering.** `seq` is stamped at the subscription boundary and totally
  orders one session. `(macrostep, round)` is the timeline key. Interleaving
  across sessions is arbitrary. **And the warning the spike earned**: a
  producer reading a live statifier session may deliver messages whose `seq`
  order does not match `(macrostep, round)` order, and may deliver `trace.*`
  messages after `session.halted` - `st-r6l9`. Consumers sort by
  `(macrostep, round)` and never treat a halt as end-of-stream. This is
  producer behavior the spec describes rather than prescribes, and it is why
  golden-trace comparison on a chart that touches that seam is a multiset or
  sorted comparison, not a byte comparison.
- **JSON discipline.** Restates ADR-0005's `$`-tagged value encoding by
  reference to the same four forms `StatifierUI.Value` implements, the
  three-way `_event.data` rule generalized to every nullable field (decision
  5), the tagged-object encoding of origins and owners with `"kind"`
  (decision 6), lexicographic object keys, ascending-index arrays for
  configurations, and **emission order for exit/entry sequences** with the
  reasoning from decision 4.
- **`session.start`.** Full schema: `version`, `states`, `transitions`,
  `contents`, optional `source`, optional `fixtures`, optional
  `parent_session` and `invokeid`. States that the location tables are built
  from the compiled Machine layer and therefore carry element spans and
  transition `cond_location`, but no attribute-level spans - `sui-qay`.
- **The nine `trace.*` schemas**, one subsection each, field by field.

## Phase 2: The message envelope, canonical JSON, and the normalizer

### Overview

The pure heart of the bead: a struct, a canonical encoder, and a total
function from `Statifier.Effect.t()` to a wire message. No process, no
session, no Machine.

### Changes Required

#### 1. The message envelope

**File**: `lib/statifier_ui/trace/message.ex` (new)
**Changes**: `StatifierUI.Trace.Message` - the in-process carrier of one wire
object.

```elixir
defmodule StatifierUI.Trace.Message do
  @moduledoc """
  One message of the trace wire format (`docs/wire-format.md`), held as a
  struct in process and rendered to the documented JSON object by `to_map/1`.
  ...
  """

  @type json ::
          nil | boolean() | integer() | float() | String.t() | [json()] |
          %{optional(String.t()) => json()}

  @type t :: %__MODULE__{
          type: String.t(),
          session: String.t(),
          seq: non_neg_integer(),
          macrostep: non_neg_integer() | nil,
          microstep: non_neg_integer() | nil,
          round: non_neg_integer() | nil,
          payload: %{optional(String.t()) => json()}
        }

  @enforce_keys [:type, :session, :seq]
  defstruct [:type, :session, :seq, :macrostep, :microstep, :round, payload: %{}]

  @spec to_map(t()) :: %{optional(String.t()) => json()}
end
```

`to_map/1` merges the envelope over the payload: `"type"`, `"session"`,
`"seq"` always; `"macrostep"`, `"microstep"`, `"round"` only when non-`nil`
(decisions 3 and 5). A payload key colliding with an envelope key is a
producer bug; `to_map/1` returns `{:error, {:reserved_payload_key, key}}`
rather than letting the envelope win silently. To keep the common path a plain
value, the check lives in a separate `validate/1` and `to_map/1` is specced
for a valid message - `Normalizer` calls `validate/1` on construction so the
invariant holds by the time anything else sees a `%Message{}`.

#### 2. Canonical JSON

**File**: `lib/statifier_ui/trace/json.ex` (new)
**Changes**: `StatifierUI.Trace.Json` - the canonical encoder that makes
ADR-0005's byte-comparable golden traces real.

```elixir
@spec encode(Message.json()) :: iodata()
@spec encode_to_string(Message.json()) :: String.t()
@spec encode_message(Message.t()) :: String.t()
@spec encode_lines([Message.t()]) :: String.t()
```

`JSON.encode!/1` alone is not enough: Erlang map iteration order is
key-insertion-independent but not lexicographic for maps above the small-map
threshold, so two runs can differ in key order. `encode/1` therefore walks the
term itself - objects emit `Enum.sort/1`-ordered keys, arrays emit in the
order given (the producer has already put them in the order the spec
requires), and every scalar and string is delegated to `JSON.encode_to_iodata!/1`
so escaping is the stdlib's problem and not ours. Roughly forty lines. It
rejects nothing: a term outside `Message.json()` is a producer bug that
`JSON.encode_to_iodata!/1` will raise on, which is the right failure for an
invariant the normalizer is supposed to have already established.

`encode_lines/1` joins `encode_message/1` results with `"\n"` and a trailing
newline - the JSON Lines shape the golden fixtures use.

#### 3. The normalizer

**File**: `lib/statifier_ui/trace/normalizer.ex` (new)
**Changes**: `StatifierUI.Trace.Normalizer` - the pure mapping.

```elixir
@type ctx :: %{session: String.t(), seq: non_neg_integer()}
@type input ::
        Statifier.Effect.t()
        | {:effect, Statifier.Effect.t()}
        | {:halted, :done | :cancelled | :budget_exhausted}
        | {:unroutable, Statifier.Effect.t()}

@spec normalize(input(), ctx()) :: {:ok, Message.t()} | {:error, term()}
@spec types() :: [String.t()]
```

- `normalize/2` accepts a bare effect, the `{:effect, _}` wrapper the session
  sends, and the two lifecycle messages. It never accepts the outer
  `{:statifier, session_id, _}` tuple - unwrapping that is the subscriber's
  job, and keeping it out here is what makes the module testable from a struct
  literal.
- It returns `{:error, {:unknown_effect, tag}}` for a tag it does not know
  rather than skipping, because a new engine effect appearing silently is the
  drift ADR-0005's Consequences warn about; the subscriber decides what to do
  with the error.
- `types/0` returns the closed, sorted list of all 23 type strings, including
  the four `session.*` types whose producers land in phases 3 and 5. It is the
  vocabulary's single definition site in code.

**Value handling.** Anything from the engine that occupies a value position -
`Event.data`, `Log.value`, `Trace.Done.donedata`, `Effect.Done.donedata`,
`Send.data`, `SendDelayed.data`, `Invoke.params`, `Invoke.content` - goes
through `StatifierUI.Value.encode/1`, and its `{:error, _}` is propagated, not
rescued. Everything structural is reduced first (decision 6): `MapSet`s to
sorted lists, atoms to strings, tuples to `"kind"`-tagged objects. This
ordering matters: `Value.encode/1` passes an unknown term through unchanged
(`value.ex:151`), so handing it a raw tuple would produce silent garbage
rather than an error.

**Private helpers** worth naming here so they are not reinvented per clause:
`event/1` (the shared `%Event{}` object, used by four message types),
`cause/1`, `origin/1` (eight variants), `owner/1` (five variants),
`indexes/1` (a list, emission order preserved), `configuration/1` (a `MapSet`,
`Enum.sort`ed), and `put_present/3` (adds a key only when the value is neither
`nil` nor `:undefined` - decision 5's mechanism, and the reason the absence
rule is applied uniformly instead of remembered clause by clause).

## Phase 3: The `session.start` definition message

### Overview

Turn a compiled `%Statifier.Machine{}` plus caller-supplied context into the
definition message that makes every later index resolvable. Pure, no process.

### Changes Required

#### 1. The manifest builder

**File**: `lib/statifier_ui/trace/manifest.ex` (new)
**Changes**: `StatifierUI.Trace.Manifest`.

```elixir
@type opts :: [
        source: String.t(),
        fixtures: map(),
        parent_session: String.t(),
        invokeid: String.t()
      ]

@spec build(Statifier.Machine.t(), session :: String.t(), opts()) ::
        {:ok, Message.t()} | {:error, term()}
@spec version() :: pos_integer()
```

`build/3` produces a `%Message{type: "session.start", seq: 0}` whose payload
is:

- `"version"` - the integer `1`, ADR-0005's initial value and the fixtures
  sidecar's convention.
- `"states"` - a list, one object per entry of `machine.states` in index
  order: `"index"`, `"kind"` (the atom stringified), `"id"` (omitted when
  `nil`), `"parent"` (omitted when `nil`), `"children"`, `"transitions"`, and
  `"location"`. Built by walking the tuple, because `id_to_index` is partial
  and there is no reverse map (`machine.ex:29`).
- `"transitions"` - one object per `t_index`: `"t_index"`, `"source"`,
  `"targets"`, `"events"` (the list-of-lists as-is), `"type"`, `"location"`,
  and `"cond_location"` when present.
- `"contents"` - one object per `c_index`: `"c_index"`, `"kind"` (the struct
  module's last segment, `Macro.underscore`d - `"log"`, `"assign"`,
  `"script"`, ...), and `"location"`. **`Content.Script` carries
  `:node_location`, not `:location`** (`machine/content/script.ex:48`), so the
  location is read as `Map.get(node, :location) || Map.get(node,
  :node_location)` and the key is omitted when both are absent. A hardcoded
  `node.location` crashes on the first `<script>`, which is the specific bug
  this note exists to prevent.
- `"source"` - the caller's SCXML string, omitted when not supplied. It cannot
  be derived: the Machine does not retain it.
- `"fixtures"` - the caller's decoded sidecar object verbatim, omitted when
  not supplied. Passed through untouched, `version` field included, per
  ADR-0005 and ADR-0003.
- `"parent_session"` and `"invokeid"` - omitted unless supplied.

`build/3` returns `{:error, {:invalid_fixtures, reason}}` when `fixtures` is
not a map, and `{:error, {:invalid_source, reason}}` when `source` is not a
binary. Nothing else can fail: every field comes from a compiled Machine,
which is by construction well-formed.

`%Location{}` renders as an object with all six integer fields, always - a
location is either wholly present or wholly absent.

## Phase 4: The bounded buffer

### Overview

A small pure module: a fixed-capacity, drop-oldest message store. Independent
of every other phase and committable on its own.

### Changes Required

#### 1. The buffer

**File**: `lib/statifier_ui/trace/buffer.ex` (new)
**Changes**: `StatifierUI.Trace.Buffer`.

```elixir
@type t :: %__MODULE__{
        capacity: pos_integer(),
        size: non_neg_integer(),
        dropped: non_neg_integer(),
        entries: :queue.queue(Message.t())
      }

@spec new(capacity :: pos_integer()) :: t()
@spec push(t(), Message.t()) :: t()
@spec to_list(t()) :: [Message.t()]
@spec size(t()) :: non_neg_integer()
@spec dropped(t()) :: non_neg_integer()
@spec clear(t()) :: t()
```

`:queue` rather than a list: `push/2` at capacity has to drop from the far
end, and a list would make that `O(n)` on every message once full. `size` is
tracked explicitly because `:queue.len/1` is `O(n)`. `to_list/1` returns
oldest-first, which is the order a log pane renders and the order
`Trace.Json.encode_lines/1` expects.

`new/1` rejects a non-positive capacity by raising `ArgumentError` - this is a
programmer argument, not an input value, and the errors-are-values rule is
about leaves that process external data.

No drop notification (decision 8): a `seq` gap is self-describing, and a
synthetic message would consume a `seq` and corrupt the counter it reports on.

## Phase 5: The subscriber process

### Overview

The only `GenServer` in this bead. It owns attach and detach, `seq` stamping,
the manifest emission, session-death handling, and the buffer. Everything it
emits is derived from messages it received (decision 9).

### Changes Required

#### 1. The subscriber

**File**: `lib/statifier_ui/trace/subscriber.ex` (new)
**Changes**: `StatifierUI.Trace.Subscriber`.

```elixir
@spec start_link(keyword()) :: GenServer.on_start()
# :machine (required)  - the compiled %Statifier.Machine{} the manifest is built from
# :source              - SCXML text for session.start, optional
# :fixtures            - decoded sidecar object for session.start, optional
# :parent_session, :invokeid - invoke-tree origin, optional
# :capacity            - buffer capacity, default 1000
# :listeners           - pids receiving {:statifier_ui, session_id, %Message{}}
# :name                - GenServer name, optional

@spec attach(server(), session :: pid(), opts :: keyword()) :: :ok
@spec detach(server()) :: :ok
@spec messages(server()) :: [Message.t()]
@spec stats(server()) :: stats()
@spec add_listener(server(), pid()) :: :ok
@spec remove_listener(server(), pid()) :: :ok
```

**The two attach paths.** `attach/3` takes `subscribe: boolean()`, default
`true`.

- *Recommended (early).* Start the subscriber, pass its pid as
  `Statifier.Session.start_link(machine, trace: true, subscribers: [sub],
  session_id: ...)`, then `attach(sub, session_pid, subscribe: false)`. The
  session already has the subscriber in its set; `attach/3` only takes the
  monitor. This is the only path that sees the initialize burst, because
  `start_link/2` runs `initialize/2` to quiescence before returning (GAP 6 /
  `st-uqo4`). The moduledoc leads with it.
- *Late.* `attach(sub, session_pid)` calls `Statifier.Session.subscribe/2`
  and monitors. The manifest gets a `diagnostic` of kind `:late_attach`, and
  the moduledoc says what was missed. `attach/3` is idempotent about the
  monitor - a second call on the same pid does not stack monitors - but it
  does not attempt to detect an existing subscription, which is why the two
  paths are distinguished by an explicit flag rather than inferred.

**Session id and the manifest.** The subscriber does not know the session id
at `start_link` time and never asks for it (decision 9). On the first
`{:statifier, session_id, _}` message it records the id, builds the manifest
with `Manifest.build/3`, emits it as `seq: 0`, then normalizes the triggering
message as `seq: 1`. If `Manifest.build/3` errors, the subscriber emits no
manifest, records the error in `stats/1`, and continues normalizing - losing
the index tables is bad, losing the whole trace is worse.

**Message handling.**

- `{:statifier, id, {:effect, effect}}` -> `Normalizer.normalize/2`, stamp,
  buffer, fan out to listeners.
- `{:statifier, id, {:halted, reason}}` -> a `session.halted` message. The
  subscriber does **not** stop, does not unsubscribe, and does not mark the
  stream complete: GAP 4 / `st-r6l9` shows `trace.*` messages arriving after
  it, and dropping them is the failure this note exists to prevent.
- `{:statifier, id, {:unroutable, effect}}` -> `session.unroutable`.
- `{:statifier, other_id, _}` where `other_id` differs from the recorded id ->
  ignored, and counted in `stats/1` as `foreign`. One subscriber watches one
  session (see "What We're NOT Doing").
- A `normalize/2` error -> counted in `stats/1` as `errors`, logged once per
  distinct reason with `Logger.warning/1`, and otherwise skipped. An unknown
  future engine effect must not kill a notebook's inspector.
- `{:DOWN, ref, :process, pid, reason}` for the monitored session -> a
  `session.terminated` message whose payload is `{"reason":
  inspect(reason)}`, status set to `:terminated`, buffer retained and still
  readable. `inspect/1` rather than a structured encoding: an exit reason is
  an arbitrary Elixir term with no language-neutral shape, and the spec says
  the field is a human-readable string, not data to branch on.
- Any other message -> ignored.

**State and `stats/1`**:

```elixir
%{
  session: String.t() | nil,
  status: :detached | :attached | :terminated,
  seq: non_neg_integer(),
  buffered: non_neg_integer(),
  dropped: non_neg_integer(),
  errors: non_neg_integer(),
  foreign: non_neg_integer(),
  diagnostics: [StatifierUI.Fixtures.diagnostic()]
}
```

Reusing `Fixtures.diagnostic/0` rather than inventing a second shape - the
map already means "a non-fatal finding with a kind, a message, a path, and a
source", and a pane that renders one can render the other. It is referenced by
type, not by moving the type: `Fixtures` owns it today and moving it would
churn a landed module for no behavioral gain.

`detach/1` unsubscribes, demonitors with `[:flush]`, sets status `:detached`,
and keeps the buffer.

**Dependency note.** `Statifier.Session` is a hard dependency, not an optional
one - `statifier` is core (ADR-0004). No `Code.ensure_loaded?/1` guard is
needed or wanted here; those are for `Kino` and `Phoenix.LiveView` only.

## Open questions

The plan makes a call on each of these and proceeds; they are recorded because
each is a place a reviewer might reasonably decide differently, or because the
answer lives in another repository's tracker. **Questions 1 and 2 are the
pre-phase-1 checkpoint** described under "Before phase 1" in Implementation
Approach, and are the only two entries here that gate anything. Questions 3
through 7 gate nothing: each is a workaround for an engine gap owned by an
`st-` bead, and the plan implements the workaround today.

1. **Does preserving exit/entry emission order need an ADR-0005 amendment?**
   ADR-0005's JSON discipline says exit/entry sets serialize "in a canonical
   order (ascending index)"; this plan preserves the engine's semantic order
   instead (decision 4), because sorting would discard the inner-to-outer exit
   order the event-log pane renders and byte-comparability is preserved
   without it. **Call made**: implement emission order, document the reasoning
   in `docs/wire-format.md`, and treat it as the spec exercising the
   field-by-field remit ADR-0005 delegated to it. **Gates phase 1**: ADR-0005
   names exit/entry sets specifically, so this needs the user's confirmation
   or a one-paragraph amendment to that record before the spec is written.
   Reversing it later rewrites the phase 5 golden fixture's bytes.

2. **Is `effect.*` the right namespace for the core effects?** ADR-0005
   sketches `log`, `done`, `budget_exhausted`, and "the send/invoke family" as
   separate namespaces. This plan uses one `effect.*` family mirroring
   `Statifier.Effect`'s tags (decision 2), because a top-level `done` would
   sit beside `trace.done` confusingly. **Call made**: `effect.*`. **Gates
   phase 1**: ADR-0005 says "namespaces", plural, and renaming later is a
   version bump under its own rule, so this is worth disagreeing with now
   rather than after a consumer exists.

3. **`round` is absent from `effect.*` messages.** Blocked on `st-nbmj`
   (GAP 1), which is statifier-ex's to decide under ADR-0010. **Call made**:
   omit the key, document the omission and the bead, and add it additively
   when the engine stamps it. Not inferred from a neighbouring effect - the
   spike explains why that silently breaks.

4. **The location tables carry no attribute-level spans.**
   `attribute_locations` lives on the Document layer, not the Machine
   (ADR-0007 Consequences; `sui-qay`), so a Machine-built table cannot give
   cond-versus-event hover granularity. **Call made**: build from the Machine,
   say so in the spec, and let `sui-qay` decide whether a Document-layer table
   ever joins `session.start`. This is exactly the caveat the spike left for
   whoever drafted this document.

5. **Nothing on the wire reports the datamodel.** GAP 2 / `st-oef3`. Polling
   `Session.snapshot/1` from the subscriber would race the session and be
   unreproducible under replay. **Call made**: reserve `session.datamodel` in
   the spec, emit nothing, and leave `sui-t36.7` to poll `snapshot/1` itself
   with a policy it owns. `sui-t36.7` should be re-read against this decision
   before it is planned, since it is the bead that most wanted the answer to
   be different.

6. **Should one subscriber follow an invoke tree?** GAP 3 / `st-fd7n` leaves a
   child session's pid undiscoverable, and whether children inherit
   `:trace`/`:subscribers` is an open upstream design call (spike Open
   question 2). **Call made**: one subscriber, one session. `session.start`
   carries the origin fields so a caller can stitch a tree from two
   subscribers today, and the format is ready for inheritance the day the
   engine offers it.

7. **Golden traces are byte-comparable only on charts that avoid `st-r6l9`.**
   The reordering seam (`<invoke>`, internal `<send>`) makes live delivery
   non-monotone and can put `trace.*` messages after a halt. **Call made**:
   the golden fixture uses a chart that avoids the seam, the test moduledoc
   says why, and the spec states that a conformance comparison on an affected
   chart is a multiset or sorted-by-key comparison. A live-versus-replay round
   trip over an internal-send chart remains the mechanical detector the spike
   describes, and it belongs to `st-r6l9`, not here.
