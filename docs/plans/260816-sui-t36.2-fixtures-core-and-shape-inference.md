# Fixtures core and shape inference implementation plan

## Overview

Implement the ADR-0003 fixtures contract in `lib/`: the consumed
`%StatifierUI.Fixtures{}` struct, the `StatifierUI.Fixtures.Source` behaviour
for host applications, the `<chart>.fixtures.json` sidecar loader for corpus
and CLI use, and a pure shape-inference module that derives display type
labels from example values. Both delivery paths converge on one struct, and
the sidecar loader ignores unknown top-level keys so a future bundle carrying
ADR-0006's `datasets` and `expressions` still parses.

Beads issue: `sui-t36.2` (parent `sui-t36`, the Livebook inspector).

## Current State Analysis

`lib/` is a scaffold. It holds exactly one module,
`lib/statifier_ui.ex:1` (`StatifierUI`, a moduledoc plus `version/0`), and
`test/` holds `test/statifier_ui_test.exs` with a single doctest-backed test.
There is no fixture code, no test support tree (`test/support/` is declared in
`mix.exs:33` for `:test` but does not exist on disk), and no `docs/plans/`
directory before this document.

What is already decided and must be honored:

- **ADR-0003** fixes the contract: two maps (scenarios, events), two delivery
  paths (behaviour, JSON sidecar with a `"version"` field), one consumed
  struct `%StatifierUI.Fixtures{scenarios: ..., events: ...}`. Function
  signatures are explicitly left to implementation time.
- **ADR-0005** fixes the JSON encoding of predicator values: JSON-native
  members map to themselves; the non-native members use reserved `$`-prefixed
  one-key objects (`{"$undefined": true}`, `{"$date": "..."}`,
  `{"$datetime": "..."}`, `{"$duration": {...}}` with all eight unit fields as
  integers). It also fixes the versioning rule: consumers ignore unknown
  fields, additive change is not a bump.
- **ADR-0006** adds `datasets` and `expressions` as additive top-level sidecar
  keys, still version 1, and is out of scope here except for the
  ignore-unknown-keys discipline it makes load-bearing.
- **ADR-0004 / `docs/architecture.md` "The dependency rule"**: core depends on
  statifier only. Nothing in this bead may reference `Kino` or
  `Phoenix.LiveView`, which is easy here - every module in this plan is core.

What the engine expects, verified against the vendored dependency source:

- `Statifier.MachineState` carries `datamodel: map()`
  (`deps/statifier/lib/statifier/machine_state.ex:349`, `@type datamodel` at
  `:366`) and enforces **string keys at every level** via
  `checked_datamodel!/1` (`:494`) and `check_keys!/2` (`:500-516`), which
  raises `ArgumentError` on any atom key other than `true`/`false`. A fixture
  scenario is destined for `MachineState.new(machine, datamodel: ...)`
  (`:434`, `:448`), so a scenario map that is not string-keyed throughout is a
  bug that must be caught at load time, not at chart-run time.
- `Statifier.Event` defaults `data: :undefined`
  (`deps/statifier/lib/statifier/event.ex:59-68`), and the three-way
  distinction ADR-0005 names is real upstream: `EventData.from_params([])`
  returns `:undefined` rather than `%{}`
  (`deps/statifier/lib/statifier/event_data.ex:99-101`, citing W3C tests
  343/488/528), and a genuine null payload is `nil`
  (`deps/statifier/lib/statifier/event_data.ex:37-42`).
- `Statifier.Evaluator.SystemVariables.event/1`
  (`deps/statifier/lib/statifier/evaluator/system_variables.ex:100-111`)
  passes `data` through verbatim while translating the other four fields'
  `nil` to `:undefined` - so `_event.data` is the one place `nil` and
  `:undefined` must not be collapsed.
- `Predicator.Types.value/0`
  (`deps/predicator/lib/predicator/types.ex:56-66`) is the closed value
  domain: booleans, integers, floats, strings, lists, `Date.t()`,
  `DateTime.t()`, a duration, `:undefined`, `nil`. A **duration is a plain
  map**, not a struct - `Predicator.Duration.new/1`
  (`deps/predicator/lib/predicator/duration.ex:35-47`) returns a bare `%{}`
  with all eight unit keys and there is no `defstruct` in that module.
- `Predicator.Undefined` (`deps/predicator/lib/predicator/undefined.ex`) owns
  the sentinel publicly: `value/0`, `undefined?/1`, `to_nil/1`, `from_nil/1`.
  Its moduledoc states the semantics this plan needs: `:undefined` is an
  absence, `nil` is the null value, and they are distinct.
- **No prior art to reuse for the tagged encoding.** Neither statifier nor
  predicator ships a `$`-tagged JSON codec for predicator values. Predicator's
  `Functions.JSONFunctions`
  (`deps/predicator/lib/predicator/functions/json_functions.ex:41-61`) is an
  expression-level `JSON.stringify`/`JSON.parse` that deliberately collapses
  the distinctions ADR-0005 preserves. The codec in this plan is new ground.

Toolchain facts that shape the design:

- Elixir is pinned to `1.18.3-otp-27` (`mise.toml`), and **the stdlib `JSON`
  module is available** (verified: `JSON.decode/1` returns
  `{:ok, term} | {:error, reason}`). Predicator already uses it. No new
  dependency is needed, and `jason` - present in `mix.lock` only as a
  transitive dependency of the optional `phoenix_live_view` - must not be
  reached for, because that would make an optional dependency load-bearing
  for core.
- The gate is `mix quality` (`.quality.exs`), with `warnings_as_errors`,
  strict Credo, Doctor at **100% moduledoc coverage** and 75% doc/spec
  (`.doctor.exs`), and an 80% coverage floor (`coveralls.json`).
  `mix quality --profile loop` is green on `main` today.

## Desired End State

Six modules under `lib/statifier_ui/` and a test support tree, such that:

1. A host module that `use`s `StatifierUI.Fixtures.Source` and defines
   `scenarios/0` and/or `example_events/0` can be turned into a
   `%StatifierUI.Fixtures{}` by `StatifierUI.Fixtures.from_source/1`.
2. `StatifierUI.Fixtures.Sidecar.load/1` reads a `<chart>.fixtures.json` file
   and returns the **same struct**, with `$`-tagged values decoded to
   predicator values, unknown top-level keys ignored and recorded as
   diagnostics, and every error returned as a value.
3. `StatifierUI.Shape.infer/1` turns any predicator value into a structured
   shape term, and `StatifierUI.Shape.label/2` renders that term as the
   display string the bead specifies (`integer`, `list<string>`,
   `map{amount: integer, ...}`).
4. `mix quality` is green, and `docs/architecture.md` no longer lists the
   sidecar naming question as open.

Verification: a convergence test asserts that a source module and a sidecar
file describing the same bundle produce structurally equal `%Fixtures{}`
values, and `mix quality` passes with coverage above the 80% floor.

### Key Discoveries

- `lib/statifier_ui.ex:1` is the only module in `lib/`; this is greenfield and
  the module layout is a decision, not a discovery.
- `.claude/wurk/codebase.md` states the intended layout: `kino/`, `live/`,
  `trace/`. Fixtures belong to none of those three - they are the core layer
  that references neither integration, which `docs/architecture.md:274-296`
  ("The dependency rule") names explicitly as where shared logic goes.
- `deps/statifier/lib/statifier/machine_state.ex:289-300` - string keys at
  every level, by construction. This is the single most consequential
  constraint on the struct's validation.
- `deps/statifier/lib/statifier/event_data.ex:99-101` - `:undefined` and `%{}`
  are genuinely different upstream, so the sidecar's key-absence rule is not
  pedantry.
- `deps/predicator/lib/predicator/duration.ex:35-47` - durations are plain
  maps with eight integer keys, which means the `$duration` decoder must
  produce a bare map and the shape inferencer must distinguish a duration map
  from an ordinary map by its exact key set.
- `deps/predicator/lib/predicator/functions/provider.ex:31` - the behaviour
  convention to match: module name is the capability, no `Behaviour` suffix,
  `@callback` on the module, implementers use `@impl <BehaviourModule>`.
- `deps/statifier/lib/statifier/event.ex:58-82` - the struct convention to
  match: `@enforce_keys`, `defstruct`, then `@type t :: %__MODULE__{...}`.

## What We're NOT Doing

- **No datasets or expressions** (ADR-0006). The struct gains no `datasets` or
  `expressions` field, and the loader parses neither. It only refrains from
  rejecting them. Implementing them is the scratchpad and
  editor-intelligence work, per ADR-0006's scope boundary.
- **No fixture-aware linting.** ADR-0003 describes walking compiled
  instruction streams for unprovided identifier references. That needs a
  compiled Machine and belongs with the editor work; this bead ships the
  artifact it would read.
- **No tier 1 or tier 2 sourcing.** `<data>` ids from a compiled Machine and
  `SystemVariables` shapes are the explorer's job (sui-t36), not the fixture
  module's. This bead ships tier 3 only.
- **No Kino or LiveView rendering.** No module here may reference either.
- **No scenario-selection policy.** ADR-0003 carries "how a scenario is
  selected when several exist" as an open question for the first consumer
  (sui-t36). This plan exposes `scenario/2` and `scenario_names/1` and takes
  no position on defaults.
- **No wire-format producer.** `StatifierUI.Value` is written here because the
  sidecar needs it and ADR-0005 already fixed its encoding; the
  trace-effect-to-JSON mapping under `lib/statifier_ui/trace/` is a different
  bead.
- **No JSON encoding of a whole bundle back to a sidecar file.**
  `StatifierUI.Value.encode/1` is implemented because a codec with only one
  direction cannot be round-trip tested, but there is no `Sidecar.write/2`.
- **No `mix` task.** ADR-0006 mentions a test helper or mix task that runs
  expectations; that arrives with expressions.

## Implementation Approach

Four phases, split on module boundaries so each is independently committable
and leaves `mix quality` green on its own. Phase 2 depends on nothing from
phase 1 and could be built in either order; phase 3 needs both.

**Module layout** (all core - referencing neither optional integration):

```
lib/statifier_ui/fixtures.ex          StatifierUI.Fixtures          (phase 1)
lib/statifier_ui/fixtures/source.ex   StatifierUI.Fixtures.Source   (phase 1)
lib/statifier_ui/shape.ex             StatifierUI.Shape             (phase 2)
lib/statifier_ui/value.ex             StatifierUI.Value             (phase 3)
lib/statifier_ui/fixtures/sidecar.ex  StatifierUI.Fixtures.Sidecar  (phase 3)
```

Two naming calls, recorded here so they are not re-litigated in review:

- **`StatifierUI.Shape`, not `StatifierUI.Fixtures.Shape`.** The bead requires
  a "pure, standalone module", and its input is any predicator value, not a
  fixture. The explorer's debug mode
  (`docs/architecture.md:167-199`) infers shapes from a *live* datamodel with
  no fixture in sight; nesting the module under `Fixtures` would make that
  read as a layering violation rather than the intended reuse.
- **`StatifierUI.Value`, not `StatifierUI.Fixtures.Value`.** ADR-0005 assigns
  the same `$`-tagged encoding to the wire format, and the trace producer will
  need it. Placing it under `Fixtures` would force the trace layer to depend
  on the fixtures layer for a codec that belongs to neither.

**Three design decisions this plan settles**, each of which the bead or an
ADR left underspecified:

1. **The behaviour has two callbacks, and `Fixtures.from_source/1` assembles
   the struct.** The bead names `scenarios/0` and `example_events/0`; ADR-0003
   says "a behaviour whose callback returns the fixtures struct". ADR-0003
   also says "exact function signatures are settled at implementation time",
   so the bead's two-callback spelling wins on specificity, and ADR-0003's
   "one consumed struct" requirement is met at `from_source/1`: every consumer
   downstream of it sees only `%Fixtures{}` and cannot tell which delivery
   path produced it. `use StatifierUI.Fixtures.Source` injects overridable
   defaults returning `%{}` for both, so a host with only events writes only
   `example_events/0`.

2. **Warnings are data on the struct, and also logged.** "Ignored with a
   warning" needs somewhere to go. `Logger.warning` alone is invisible to a
   test that wants to assert the ignore happened, and `CLAUDE.md` says errors
   are values. So `%Fixtures{}` carries `diagnostics: [diagnostic()]`
   (`[]` for the behaviour path), the loader populates it, **and** the loader
   emits one `Logger.warning` per diagnostic so a corpus or CLI run surfaces
   it without a caller having to look. The extra field does not contradict
   ADR-0003: the record fixes two maps and one struct, not a field count, and
   ADR-0005's inline-on-the-wire clause carries the sidecar's raw JSON object
   verbatim, not this struct.

3. **The bead's "predicator 6.0 semantics" is read as the semantics predicator
   documents today.** The installed version is 8.0.0
   (`mix.lock`, `deps/predicator/mix.exs:5`), reached through
   `{:statifier, github: ...}` which requires `~> 8.0`. Predicator 8.0's own
   type documentation
   (`deps/predicator/lib/predicator/types.ex:52-55`) states exactly what the
   bead asks for - `:undefined` is an absence, `nil` is the null value,
   `nil === :undefined` is false - so the version number in the bead text is
   stale, not a different contract. Implementation targets 8.0.

## Phase 1: The fixtures struct and the Source behaviour

### Overview

The consumed type and the host-application delivery path. After this phase a
host can express a fixture bundle in Elixir and get a validated struct back,
with no JSON involved.

### Changes Required

#### 1. The struct

**File**: `lib/statifier_ui/fixtures.ex` (new)
**Changes**: `StatifierUI.Fixtures` - the struct ADR-0003 names, its
constructor, its validation, and read accessors.

```elixir
defmodule StatifierUI.Fixtures do
  @moduledoc """
  Example data a host supplies for a chart: named scenario datamodels and
  example event payloads (ADR-0003).
  ...
  """

  @type scenario_name :: String.t()
  @type event_name :: String.t()
  @type datamodel :: %{optional(String.t()) => term()}
  @type diagnostic :: %{kind: atom(), message: String.t(), path: [String.t()]}

  @type t :: %__MODULE__{
          scenarios: %{optional(scenario_name()) => datamodel()},
          events: %{optional(event_name()) => term()},
          diagnostics: [diagnostic()]
        }

  defstruct scenarios: %{}, events: %{}, diagnostics: []

  @spec new(keyword()) :: {:ok, t()} | {:error, term()}
  @spec from_source(module()) :: {:ok, t()} | {:error, term()}
  @spec scenario(t(), scenario_name()) :: {:ok, datamodel()} | :error
  @spec scenario_names(t()) :: [scenario_name()]
  @spec event(t(), event_name()) :: {:ok, term()} | :error
  @spec event_names(t()) :: [event_name()]
end
```

Validation rules `new/1` enforces, returning `{:error, reason}` rather than
raising (never rescue-to-default; the leaf returns the error):

- `scenarios` and `events` are maps with `String.t()` keys.
- Every scenario value is a map whose keys are strings **at every level**,
  mirroring `Statifier.MachineState.check_keys!/2`
  (`deps/statifier/lib/statifier/machine_state.ex:500-516`). Recursion
  descends maps and lists and stops at structs (`Date`, `DateTime`).
  Rejecting atom keys here converts a runtime `ArgumentError` deep in the
  engine into a load-time error value.
- Every event value is a legal `_event.data`: the three-way
  `:undefined` / `nil` / map distinction is preserved verbatim, so `nil` is
  accepted as a value and never normalized. An event whose key is absent from
  the map means "this event has no fixture", not "empty data".
- `scenario_names/1` and `event_names/1` return keys in
  `Enum.sort/1` order, matching ADR-0005's canonical-order rule so two
  renderings of one bundle are comparable.

`from_source/1` calls `module.scenarios()` and `module.example_events()` and
routes the results through `new/1`, so both delivery paths share exactly one
validation implementation. It checks `function_exported?/3` after
`Code.ensure_loaded/1` and returns `{:error, {:not_a_source, module}}` when
the module does not implement the behaviour.

#### 2. The behaviour

**File**: `lib/statifier_ui/fixtures/source.ex` (new)
**Changes**: `StatifierUI.Fixtures.Source` - the callbacks and the `__using__`
defaults. Convention matched from
`deps/predicator/lib/predicator/functions/provider.ex:31`.

```elixir
defmodule StatifierUI.Fixtures.Source do
  @callback scenarios() :: %{optional(String.t()) => map()}
  @callback example_events() :: %{optional(String.t()) => term()}

  defmacro __using__(_opts) do
    quote do
      @behaviour StatifierUI.Fixtures.Source

      @impl StatifierUI.Fixtures.Source
      def scenarios, do: %{}

      @impl StatifierUI.Fixtures.Source
      def example_events, do: %{}

      defoverridable scenarios: 0, example_events: 0
    end
  end
end
```

**Changes**: a source module used by the phase 1 tests and reused by the

**File**: `test/support/fixtures/events_only_source.ex` (new)

#### 4. Tests

## Phase 2: Shape inference

### Overview

A pure, standalone module that turns a predicator value into a structured
shape term and renders that term as a display label. Depends on nothing in
phase 1 and is independently committable.

### Changes Required

#### 1. The inference module

**File**: `lib/statifier_ui/shape.ex` (new)
**Changes**: `StatifierUI.Shape` - `infer/1` and `label/2`.

The structured term, because the explorer tree wants a label but editor
completions will want the keys:

```elixir
@type t ::
        :boolean
        | :integer
        | :float
        | :string
        | :date
        | :datetime
        | :duration
        | :null
        | :undefined
        | :unknown
        | {:list, t() | :empty}
        | {:map, %{optional(String.t()) => t()}}
        | {:union, [t()]}

@spec infer(term()) :: t()
@spec label(t(), keyword()) :: String.t()
```

Inference rules, settled here so the implementation has no judgment calls
left:

- Scalars map to their atoms. `is_boolean/1` is checked **before**
  `is_integer/1`, which is not an issue in Elixir but is stated because the
  order matters for the `is_number` branches: `is_integer` before `is_float`.
- `%Date{}` -> `:date`, `%DateTime{}` -> `:datetime`. Checked before the
  generic map branch, since both are structs.
- A **plain map whose key set is exactly the eight duration unit keys**
  (`years months weeks days hours minutes seconds milliseconds`, as atoms,
  per `deps/predicator/lib/predicator/duration.ex:35-47`) with all-integer
  values -> `:duration`. Any other map -> `{:map, ...}`.
- `nil` -> `:null`; `:undefined` -> `:undefined`. Never collapsed into each
  other, per `deps/predicator/lib/predicator/undefined.ex` and ADR-0005.
  These are the predicator 8.0 semantics discussed under Implementation
  Approach.
- Lists: `[]` -> `{:list, :empty}`. A non-empty list infers each element and
  unifies: identical shapes collapse to that shape; differing shapes produce
  `{:union, sorted_unique_shapes}`. Map elements unify by taking the union of
  their key sets, with a key present in only some elements unified against
  `:undefined` - which is the honest reading of ADR-0003's accepted cost that
  "a single example cannot express optionality", made visible rather than
  silently dropped.
- Maps: keys are normalized to strings (an atom key stringifies) and values
  are inferred recursively.
- Anything outside the predicator value domain (a tuple, a pid, an unknown
  struct) -> `:unknown`. `infer/1` never raises; it is total over `term()`.

Label rules, matching the bead's examples exactly:

- Scalars render as their name: `integer`, `float`, `string`, `boolean`,
  `date`, `datetime`, `duration`, `null`, `undefined`, `unknown`.
- `{:list, shape}` -> `list<inner>`; `{:list, :empty}` -> `list<>`.
- `{:map, pairs}` -> `map{key: inner, key2: inner2}` with keys in
  `Enum.sort/1` order (ADR-0005 canonical ordering), so a label is stable
  across two renderings of the same value.
- `{:union, shapes}` -> `a|b`, members in label order.
- Truncation, which is what the bead's `map{amount: integer, ...}` ellipsis
  is: `label/2` takes `:max_keys` (default 4) and `:max_depth` (default 3).
  Beyond `:max_keys`, remaining pairs render as a single `...`. At
  `:max_depth`, a nested `{:map, _}` renders as `map{...}` and a nested
  `{:list, _}` as `list<...>`. Truncation is a **label** concern only;
  `infer/1` recurses fully, because completions need the whole tree.

## Phase 3: The value codec and the JSON sidecar loader

### Overview

The corpus and CLI delivery path: read `<chart>.fixtures.json`, decode
ADR-0005's `$`-tagged values, ignore unknown top-level keys with a
diagnostic, and produce the same struct phase 1 produces.

### Changes Required

#### 1. The value codec

**File**: `lib/statifier_ui/value.ex` (new)
**Changes**: `StatifierUI.Value` - `decode/1` and `encode/1` for the ADR-0005
encoding of `Predicator.Types.value/0`.

```elixir
@spec decode(term()) :: {:ok, term()} | {:error, term()}
@spec encode(term()) :: {:ok, term()} | {:error, term()}
```

Decoding rules, straight from ADR-0005's "JSON discipline":

- JSON-native values map to themselves; JSON `null` decodes to `nil` (present
  and null), never to `:undefined`.
- `{"$undefined": true}` -> `:undefined`.
- `{"$date": "2026-08-16"}` -> `Date.from_iso8601/1`, error propagated as a
  value.
- `{"$datetime": "..."}` -> `DateTime.from_iso8601/1`, likewise.
- `{"$duration": {...}}` -> a plain map with all eight unit keys as atoms and
  integer values, missing units defaulting to `0`, non-integer or unknown unit
  keys an error. Produced as a bare map, not a struct, because
  `deps/predicator/lib/predicator/duration.ex` has no struct.
- A **one-key object whose key starts with `$` but is not one of the four**
  is an error, not a passthrough. ADR-0005 reserves the `$`-prefixed one-key
  shape, so an unrecognized one is a spec violation on the producer's side and
  silently treating it as a host map would be exactly the misread the reserved
  shape exists to prevent.
- A multi-key object containing a `$`-prefixed key is an ordinary host map;
  only the one-key shape is reserved.
- Decoding recurses through lists and map values.

`encode/1` is the inverse, present so the codec is round-trip testable. It is
not wired to any writer.

#### 2. The sidecar loader

**File**: `lib/statifier_ui/fixtures/sidecar.ex` (new)
**Changes**: `StatifierUI.Fixtures.Sidecar` - path derivation, read, parse,
validate, convert.

```elixir
@spec sidecar_path(Path.t()) :: Path.t()
@spec load(Path.t()) :: {:ok, StatifierUI.Fixtures.t()} | {:error, term()}
@spec load_for_chart(Path.t()) :: {:ok, StatifierUI.Fixtures.t()} | {:error, term()}
@spec from_json(map()) :: {:ok, StatifierUI.Fixtures.t()} | {:error, term()}
```

- `sidecar_path/1` implements ADR-0003's naming: `payment.scxml` ->
  `payment.fixtures.json`, by replacing the final extension. A path with no
  extension gets `.fixtures.json` appended.
- `load_for_chart/1` derives the path and calls `load/1`; a **missing sidecar
  is `{:error, :enoent}`**, not an empty bundle. "The chart has no fixtures"
  is a caller-level decision (an explorer shows an empty tree; a corpus runner
  may not care), and inventing an empty struct here would hide a typo'd path.
- `load/1` reads the file, decodes with the stdlib `JSON.decode/1` (Elixir
  1.18, already used by predicator - no new dependency, and notably **not**
  `jason`, which reaches this repo only through the optional
  `phoenix_live_view` and must not become load-bearing for core), and hands
  the map to `from_json/1`. Every failure is an error value; nothing rescues
  to a default.
- `from_json/1`:
  - Requires the top-level term to be a JSON object; a list or scalar is
    `{:error, {:invalid_sidecar, ...}}`.
  - Requires `"version"` to be present and an integer. A missing or non-integer
    version is an error - ADR-0005's ignore-unknown rule is about unknown
    *keys*, and a bundle that does not declare its version cannot be reasoned
    about at all.
  - Accepts `version == 1`. A **higher** integer version is accepted with a
    `:future_version` diagnostic rather than rejected, because ADR-0005
    defines a bump as "a consumer of the old version would misread the
    stream", which is a claim this loader cannot evaluate; refusing to read
    would make every future bump break every existing corpus file. A version
    below 1 is an error.
  - Reads `"scenarios"` and `"events"`, each optional and each defaulting to
    `%{}`, running every value through `StatifierUI.Value.decode/1`.
  - **Ignores every other top-level key**, appending one
    `%{kind: :unknown_key, ...}` diagnostic per key and emitting one
    `Logger.warning` per diagnostic. This is the ADR-0006 extension-friendly
    requirement, and a sidecar carrying `"datasets"` and `"expressions"` loads
    cleanly with two diagnostics.
  - Passes the decoded maps through `StatifierUI.Fixtures.new/1`, so the
    sidecar path inherits phase 1's validation - including the string-key
    invariant, which JSON satisfies natively but which the shared code path
    documents rather than assumes.
  - Preserves the `_event.data` three-way distinction: a key absent from
    `"events"` is no fixture, a JSON `null` value decodes to `nil`, and
    `{}` decodes to `%{}`.

- `Fixtures.from_source(PaymentSource)` versus
  `Sidecar.load("test/support/fixtures/payment.fixtures.json")` - the
  plain-scalar bundle.
- `Fixtures.from_source(TaggedSource)` versus
  `Sidecar.load("test/support/fixtures/tagged.fixtures.json")` - the bundle

`Date`, `DateTime`, durations, or `:undefined`. The tagged pair is what makes
"one struct, indifferent to which path the data arrived by" a claim the gate
can falsify.

the test asserts that behavior deliberately rather than treating it as a bug);
an empty list versus a list of empty maps; a sidecar with `"scenarios"` but no
`"events"`.
