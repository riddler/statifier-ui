# Research: trace coverage against the inspector needs

**Date**: 2026-08-16T18:27:17-0600
**Git Commit**: dcd5498dcc5aaf00e098b5036ad8effb4b68e776
**Branch**: sui-t36.1-trace-coverage-spike
**Bead**: sui-t36.1

## Research question

Run a real `Statifier.Session` with trace enabled and confirm the emitted
trace-effect vocabulary suffices for the inspector panes: event dequeued,
transitions selected, exit set, entry set, content executed, macrostep
stable, done, and invoke passes - each stamped with `(macrostep, round)`
counters and constraint-3 identities, delivered to subscribers as
`{:statifier, session_id, {:effect, effect}}` messages.

## Method

This is an **observed** result, not a source-reading summary. Four throwaway
scripts were run with `mix run` against `deps/statifier` as vendored at
commit-time, each starting a real `Statifier.Session` over a heredoc SCXML
fixture, subscribing the script's own pid, driving events, and printing every
`{:statifier, session_id, message}` tuple received:

- **Chart A** - eventless (NULL) transition round, a three-round macrostep,
  parallel regions with two `<final>` children, `<onentry>`/`<onexit>`/
  `<log>`/`<assign>`, `done.state.*`, and a top-level `<final>` with
  `<donedata>`.
- **Chart B/C** - `<invoke type="http://www.w3.org/TR/scxml/" src=...
  autoforward="true">` with a `<finalize>` block, run both without and with
  `Statifier.Supervisor` started.
- **Chart D** - three probes: an `error.execution` from a bad `<assign>`, a
  livelocked eventless ping-pong against `max_macrostep_rounds: 5`, and a
  `<send delay="20ms">`.

Every struct quoted below is verbatim from that output. The scratch scripts
were kept outside the repository and are not committed; no UI code was
written and nothing under `deps/` was modified (ADR-0002, statifier ADR-0012).

## Summary

**The vocabulary is sufficient. All nine trace effects were observed, and
every one of the eight inspector needs on the bead is COVERED by a real
effect, in order, on a real subscriber.** The message shape stated on the
bead is confirmed exactly.

The gaps that exist are not gaps in the *vocabulary*; they are gaps around
it, and none of them blocks a first inspector pane:

- `round` is stamped on all nine trace effects but is **missing on most core
  effects** (`:log`, `:invoke`, `:cancel_invoke`, `:autoforward`, `:done`,
  `:send_delayed`, and - per a follow-up pass, see GAP 1 - `:send` and
  `:cancel` too). `:budget_exhausted` is the one core effect that carries it.
- Nothing on the stream reports a **datamodel change**. `<assign>` is visible
  only as a `Trace.ContentExecuted` naming the `c_index` that ran; a data
  pane has to poll `snapshot/1` for values.
- A session's **child invocations are not introspectable**, so a session-tree
  pane cannot find a child's pid or `session_id` to subscribe to it. Child
  effects go only to the child's own subscribers.
- Effect **delivery order can diverge from the `(macrostep, round)` ordering
  key** when performing an `:invoke` effect re-enters the core; observed on
  the invoke-failure path. A follow-up pass confirmed this is reachable on a
  plain success path too (an internal `<send>` in an `<onentry>`, nothing
  failing), and that the reordered trace effects arrive **after**
  `{:halted, :done}` - see GAP 4.
- `Statifier.start_session/2` **deadlocks** on a document whose `<invoke>`
  resolves at initialize time.

A follow-up pass also ran `Statifier.Replay` against two of these charts:
identical byte-for-byte on a plain delayed-send chart, and on the
reordering-prone internal-send chart above, the same effect multiset and
terminal state but in the correctly ordered stream that live delivery does
not produce (Open question 4, now settled).

Seven gaps were filed as `st-` beads out of the original spike; a follow-up
direction pass ran the open questions recorded below, settled most of them,
and turned up one more bug, now filed as an eighth bead, st-5fbw. All eight
are in the GAPS section below, per ADR-0010, each carrying a
`mirrors: sui-t36.1` first line.

## 1. The enable-trace and subscription API, as observed

Three moving parts, all confirmed:

**Compile.** `Statifier.compile(source) :: {:ok, Machine.t()} | {:error,
[error()]}` (`deps/statifier/lib/statifier.ex:68`). The `%Machine{}` is the
identity table every trace index resolves against, and it is a plain value
the host already holds.

**Start with trace on.** `:trace` is one of the `Statifier.MachineState.new/2`
options passed straight through `Statifier.Session.start_link/2`
(`deps/statifier/lib/statifier/session.ex:354`):

```elixir
{:ok, pid} =
  Statifier.Session.start_link(machine,
    trace: true,
    subscribers: [self()],
    invoke_source: fn _src -> {:ok, child_machine} end
  )
```

`:subscribers` (default `[]`) is monitored from the start;
`Statifier.Session.subscribe/2` and `unsubscribe/2`
(`deps/statifier/lib/statifier/session.ex:472-476`) manage the set
afterward. `start_link/2` runs `initialize/2` to quiescence **before it
returns**, so a pid subscribed with `subscribe/2` after the fact misses the
whole initialize burst - passing `:subscribers` at start is the only way to
see it (GAP 6).

The gate itself is `Statifier.Effect.trace/3`
(`deps/statifier/lib/statifier/effect.ex:159`), a macro that expands to `[]`
with its `fields` never evaluated when `machine_state.trace` is false. The
untraced path allocates nothing, so an inspector is genuinely opt-in.

**The message shape - confirmed as stated on the bead.** Every subscriber
message is `{:statifier, session_id, message}`
(`deps/statifier/lib/statifier/session.ex:1252`), and the observed `message`
values were:

| `message` | observed |
|---|---|
| `{:effect, effect}` | yes, for every core and trace effect, in one interleaved stream |
| `{:halted, :done \| :cancelled \| :budget_exhausted}` | yes - `{:halted, :done}` and `{:halted, :budget_exhausted}` |
| `{:unroutable, effect}` | never observed; every effect routed |

`session_id` is the `sess_` string, matching `Statifier.Session.session_id/1`
and `status/1`'s `:session_id`. Trace effects are ordinary members of the same
stream, never a side channel - as `docs/observability.md` constraint 2
promises.

**Driving and reading back.** `Statifier.Session.send_event(pid, "go")`
accepts a bare name or an `%Event{}`; `status/1` returns a small projection
(`%{session_id, status, configuration, macrostep, microstep, round,
queued_events, pending_timers}`) with the configuration already translated to
**state id strings**, while `snapshot/1` returns the whole `%MachineState{}`.

## 2. Inventory of effects actually observed

All nine trace effects appeared. Every example below is verbatim output.

### `Trace.EntrySet` - Appendix D `enterStates` / `computeEntrySet`

```elixir
%Statifier.Effect.Trace.EntrySet{
  indexes: [4, 5, 6, 8, 9], macrostep: 2, microstep: 3, round: 2}
```

Emitted before any state is entered, in entry order. Parallel entry is
visible as one effect listing the parallel and both regions' descendants.

Note for the pane: Elixir's `inspect/1` prints a list of small integers as a
charlist (`indexes: ~c"\a\n"` was really `[7, 10]`). A pure display artifact,
but one worth writing a formatter for on day one.

### `Trace.ExitSet` - Appendix D `exitStates` and `exitInterpreter`

```elixir
%Statifier.Effect.Trace.ExitSet{
  indexes: [10, 8, 7, 5, 4], macrostep: 3, microstep: 2, round: 3}
```

Exit order (inner to outer) is preserved. Both emission sites were observed:
the ordinary microstep, and `exit_interpreter/1`'s sweep of the whole
configuration at termination (`indexes: [11, 0]`).

### `Trace.TransitionsSelected` - both selection functions

```elixir
%Statifier.Effect.Trace.TransitionsSelected{
  t_indexes: [4, 5], event: %Statifier.Event{name: "finish", ...},
  macrostep: 3, microstep: 0, round: 0}
```

`event: nil` marks an eventless (NULL) round, which is how the pane
distinguishes `select_eventless_transitions/1` from `select_transitions/2`.
The empty set is emitted too (`t_indexes: []`), including the terminal
eventless probe that ends a macrostep - so "nothing matched" is a positive
observation, never an absence. Parallel regions produce a multi-transition
selection in one effect (`[4, 5]`).

### `Trace.EventDequeued` - the head of the outer/inner loop

```elixir
%Statifier.Effect.Trace.EventDequeued{
  event: %Statifier.Event{
    name: "done.state.left", type: :platform, data: :undefined,
    cause: %Statifier.Event.Cause{
      origin: {:state, 7}, macrostep: 3, microstep: 1, round: 0},
    invokeid: nil, origin: nil, origintype: nil, sendid: nil},
  from: :internal, macrostep: 3, microstep: 1, round: 1}
```

`from: :external | :internal` separates the two queues. The `%Event{}` is
carried whole, and `Event.Cause` is a real payoff for a causality pane:
`{:state, 7}` says which state's completion raised `done.state.left`, stamped
with the step it was raised at (constraint 4). Observed cause origins across
the probes: `{:state, index}`, `{:content, c_index, owner}`, and
`{:invoke, state_index, invoke_index}`.

### `Trace.ContentExecuted` - a block of executable content ran

```elixir
%Statifier.Effect.Trace.ContentExecuted{
  owner: {:onentry, 1, 0}, c_indexes: [0, 1],
  macrostep: 1, microstep: 1, round: 0}
```

`owner` was observed in four shapes: `{:onentry, state_index, ordinal}`,
`{:onexit, state_index, ordinal}`, `{:transition, t_index}`, and
`{:finalize, state_index, invoke_index}`. A transition with no content still
emits the effect with `c_indexes: []`, which keeps the microstep's shape
uniform for a stepper.

### `Trace.MacrostepStable` - quiescence

```elixir
%Statifier.Effect.Trace.MacrostepStable{
  configuration: MapSet.new([0, 4, 5, 6, 8, 9]),
  macrostep: 2, microstep: 3, round: 3}
```

The full configuration (ancestors included, statifier ADR-0005), as indexes.

### `Trace.Done` - top-level final / `exitInterpreter`

```elixir
%Statifier.Effect.Trace.Done{
  donedata: %{"hops" => 3}, configuration: MapSet.new([0, 11]),
  macrostep: 3, microstep: 2, round: 4}
```

Always immediately followed by the core `{:done, %Statifier.Effect.Done{}}`
built from the same binding, then `{:halted, :done}`. `<donedata><param>`
evaluation is visible (`%{"hops" => 3}` is the counted `<assign>` result).

### `Trace.InvokePass` - Appendix D's invoke pass, spec 6.4

```elixir
%Statifier.Effect.Trace.InvokePass{
  state_indexes: [0, 1], invoke_ids: ["kid"],
  macrostep: 1, microstep: 1, round: 1}
```

`state_indexes` is the whole `statesToInvoke` walk in entry order, including
states owning no `<invoke>`; `invoke_ids` are only the invocations actually
started. Emitted on every pass, including the empty one.

### `Trace.FinalizeAutoforward` - spec 6.4/6.5, once per external event

```elixir
%Statifier.Effect.Trace.FinalizeAutoforward{
  event: %Statifier.Event{name: "done.invoke.kid", type: :external,
    invokeid: "kid", origin: "#_scxml_sess_06g0t755kmnysxt5a1c33dt1km",
    origintype: "http://www.w3.org/TR/scxml/#SCXMLEventProcessor", ...},
  finalized: ["kid"], forwarded: ["kid"],
  macrostep: 3, microstep: 0, round: 0}
```

## 4. Counters and constraint-3 identities

### What constraint 3 means

Determinable, and quoted directly: `deps/statifier/docs/observability.md`,
"Constraint 3: the Machine retains locations and identities". Its content is

- states, transitions, and executable-content nodes on the Machine retain
  their source location;
- SCXML transitions and content have no IDs, so the compiler assigns each a
  **stable document-order index per machine** - `index` for states, `t_index`
  for transitions, `c_index` for content nodes;
- trace effects and error metadata reference those indexes, and tooling maps
  them back to nodes and locations;
- expression-level locations are in scope too, via predicator's span table
  (statifier ADR-0014).

So "constraint-3 identities" is precisely: integer indexes, never resolved
structs. That is exactly what was observed - no `%Machine.State{}`,
`%Machine.Transition{}`, or content struct ever appeared inside a trace
payload. `Trace.FinalizeAutoforward` and `Trace.InvokePass` carry
`invoke_id` **strings** instead, which is the author's own `<invoke id>` and
is equally stable.

Resolution back to nodes is `Statifier.Machine.at/2`,
`Statifier.Machine.transition/2`, and `Statifier.Machine.content/2`
(`deps/statifier/lib/statifier/machine.ex:169-187`), plus
`machine.id_to_index` for the id-string map.

### Counters

`macrostep`, `microstep`, and `round` are `@enforce_keys` on **all nine**
trace payload structs, stamped by each module's `new/2` from the
`%MachineState{}` rather than at the call site - so no trace effect can be
emitted without them. Observed behaviour matches statifier ADR-0020:
`begin_macrostep` resets `microstep` and `round`, and `round` advances even
in a round that runs no microstep (the terminal eventless probe bumped
`round` while `microstep` held).

The exception is the core effects. Observed field sets:

| effect | macrostep | microstep | round |
|---|---|---|---|
| all nine `Trace.*` | yes | yes | yes |
| `BudgetExhausted` | yes | yes | **yes** |
| `Log`, `Invoke`, `CancelInvoke`, `Autoforward`, `Done`, `SendDelayed`, `Send`, `Cancel` | yes | yes | **no** |
| `Event.Cause` (on `%Event{}`) | yes | yes | yes |

Since ADR-0005 makes `(macrostep, round)` the ordering key of the wire
format's envelope, a `%Log{}` cannot be placed on that timeline without
inferring `round` from the trace effect beside it. That is GAP 1. A
follow-up pass added `Send` and `Cancel` to this row - both were confirmed
producible (section 2) and both share the same missing-`round` problem, and
neither was in st-nbmj's original enumeration.

## 5. Source locations

**Retained on the Machine, absent from the effects - by design.** No trace
payload carries a `%Parser.Location{}`; they carry indexes, and the consumer
resolves. Verified by resolving observed indexes:

```elixir
%Statifier.Machine.Transition{
  t_index: 0, source: 1, targets: [2], events: [["go"]], cond: nil,
  type: :external, content: [],
  location: %Statifier.Parser.Location{start_line: 13, start_column: 9,
    start_offset: 417, end_line: 13, end_column: 47, end_offset: 455},
  cond_location: nil}
```

Locations are full spans - line, column, **and byte offset**, start and end -
which is enough to drive a CodeMirror decoration directly with no
re-derivation (ADR-0007's text-first stance). `%Machine.State{}` carries
`location`; `%Machine.Content.Log{}` carries both `location` and a separate
`expr_location`, plus the compiled expression as
`{:compiled, %Predicator.Compiled{instructions:, positions:,
segment_positions:}, "'warm'"}` - the source string and predicator's span
table travel together (statifier ADR-0014), so an expression pane can
highlight a failing subexpression.

The error path confirms this end to end: an `<assign>` over an unbound
variable produced an `error.execution` whose `data` was
`%Statifier.Evaluator.Error{source: "undefined_var + 1", error:
%Predicator.Errors.UndefinedVariableError{...}, span: {{1, 1}, {1, 14}}}`,
with `cause.origin: {:content, 0, {:onentry, 1, 0}}`. Both the failing
subexpression span and the owning content node are named.

## 6. GAPS - filed `st-` beads

Per ADR-0010 and the CLAUDE.md cross-repo rule, each of these changes files
in statifier-ex and is therefore an `st-` bead worked there. The original
seven are filed, each with `mirrors: sui-t36.1` as the first line of its
description; nothing under `deps/` was touched from here. A follow-up
direction pass that ran the open questions below turned up one more, filed
as st-5fbw and marked below as a follow-up finding rather than one of the
original seven.

### GAP 1 - Stamp `round` on every effect, not only the trace effects (st-nbmj)

**Title**: `Stamps round on the core effects`

**Description**: `Log`, `Invoke`, `CancelInvoke`, `Autoforward`, `Done`, and
`SendDelayed` carry `macrostep` and `microstep` but not `round`.
`BudgetExhausted` and all nine `Trace.*` payloads carry all three.
`docs/observability.md` constraint 4 makes `(macrostep, round)` the ordering
key, and ADR-0020 notes `round` is the one counter that advances in a round
running no microstep, so `(macrostep, microstep)` is not a substitute.

**Why the UI needs it**: statifier-ui ADR-0005 puts `(macrostep, round)` in
the wire-format envelope of *every* message. Without it, a `<log>` line or a
started invocation can only be placed on the timeline by borrowing `round`
from whichever trace effect happens to sit next to it in the list - a
consumer-side inference that silently breaks the moment two rounds emit into
one batch.

**Follow-up finding.** A direction pass exercised the moduledoc's other two
"not yet produced" rows and found both real and both missing `round` too:
immediate `%Effect.Send{}` was observed, and so was
`%Effect.Cancel{send_id: "later", c_index: 1, owner: {:onentry, 2, 0},
macrostep: 2, microstep: 2}`. Neither was in the original enumeration above.
st-nbmj now carries a note adding them, making the full list of core effects
missing `round`: Log, Invoke, CancelInvoke, Autoforward, Done, SendDelayed,
Send, Cancel.

### GAP 2 - A datamodel-change effect (st-oef3)

**Title**: `Emits a datamodel change effect for <assign>`

**Description**: `<assign>` is observable only as a `Trace.ContentExecuted`
naming the `c_index` that ran. Nothing on the effect stream says which
location was written, or with what value. `<log>` is the sole content node
whose result reaches a consumer, via `Effect.Log`'s `value`. An effect
carrying at minimum `{c_index, location_path, new_value}` - and ideally the
prior value - would close it.

**Why the UI needs it**: a data pane is one of the first inspector panes, and
statifier-ui ADR-0007's text-first stance means the diagram is a projection
of the trace, not of a polled snapshot. Reconstructing the datamodel by
calling `Session.snapshot/1` after each effect races the session, defeats
replay from a recorded trace entirely (the values are simply not in the
trace), and is impossible for a non-Elixir consumer of the ADR-0005 wire
format.

### GAP 3 - Introspect a session's live invocations (st-fd7n)

**Title**: `Exposes a session's active invocations`

**Description**: `Statifier.Session` holds `state.invocations` (a private
`Statifier.Session.Invocations` table of `%{session_id, pid, monitor_ref,
autoforward}` per `invoke_id`), and there is no public accessor. A child
session's effects go only to that child's own subscribers, so an observer of
the parent sees `Effect.Invoke`, `Trace.InvokePass`, and later
`done.invoke.<id>`, but never anything the child did. The child's
`session_id` is recoverable only by scraping the `origin:
"#_scxml_sess_..."` field off an event the child happened to send back.

**Why the UI needs it**: an inspector for a document with `<invoke>` has to
draw a session tree and let the user step into a child. That needs (a) an
accessor listing `{invoke_id, session_id, pid}` for live invocations, and
ideally (b) a way to have children inherit the parent's `:trace` and
`:subscribers`, so attaching once traces the whole tree.

### GAP 4 - Effect delivery order can violate the `(macrostep, round)` key (st-r6l9)

**Title**: `Preserves effect order when :invoke re-enters the core`

**Description**: Observed on the invoke-failure path (no
`Statifier.SessionSupervisor` running, so `start_child` takes the
`error.communication` route). Delivery order to the subscriber was:

```
Trace.TransitionsSelected  macrostep 1  round 1
Effect.Invoke              macrostep 1
Trace.TransitionsSelected  macrostep 1  round 2
Trace.EventDequeued        macrostep 1  round 2   # error.communication
...
Trace.InvokePass           macrostep 1  round 3   state_indexes: []
Trace.MacrostepStable      macrostep 1  round 3
Trace.InvokePass           macrostep 1  round 1   invoke_ids: ["kid"]   <-- late
Trace.MacrostepStable      macrostep 1  round 1   <-- late
```

The `round 1` pair arrives *after* the `round 3` pair. Performing the
`:invoke` effect re-enters the core with the error event before the remainder
of the original effect list is forwarded. On the success path (GAP 5's
workaround applied) the same trace is perfectly ordered, so this is specific
to an effect whose performance drives the core again mid-batch.
`docs/observability.md` constraint 2 says trace effects have "same ordering
guarantees, same delivery path"; here the guarantee holds for the *list* but
not for what reaches a subscriber.

**Why the UI needs it**: an append-only timeline pane that trusts arrival
order will render the invoke pass in the wrong place. A consumer can sort by
`(macrostep, round)` instead, but only once GAP 1 gives every effect a
`round` - and a duplicated `MacrostepStable` for the same `(macrostep, round)`
is still ambiguous.

**Follow-up finding: reachable on a success path, and worse than written
above.** A direction pass reproduced the same reordering with nothing
failing anywhere - `<send target="#_internal">` in an `<onentry>`. Chart:
`a -go-> b`, onentry internal send "ping", `b -ping-> final c`. Captured
arrival order:

```
11  Effect.Send                m=2 mi=1
12  Trace.TransitionsSelected  m=2 r=2      <- re-entry effects begin
...
19  Trace.Done                 m=2 r=3
20  Effect.Done
21  {:halted, :done}
22  Trace.ContentExecuted      m=2 r=0      <- tail of the original batch, late
23  Trace.TransitionsSelected  m=2 r=1
24  Trace.InvokePass           m=2 r=1
25  Trace.MacrostepStable      m=2 r=1
```

A control chart using a targetless `<send>` (which goes to the external self
queue via `{:enqueue_event, _}` rather than `deliver_internal`) is perfectly
monotone, which localizes the mechanism: `perform_instruction({:deliver,
:internal, ...})` and `({:raise, ...})` call `deliver_internal` mid-batch at
`deps/statifier/lib/statifier/session.ex:820-828`, and the re-entry's effects
are notified before the rest of the original instruction list is reduced.
Any mid-batch crossing of that seam reorders - the invoke-failure path above
was one instance, and an unsupported `<invoke type>` at initialize (GAP 8 /
st-5fbw below) is a third.

Sharper consequence than the original write-up: trace effects can arrive
**after** `{:halted, :done}` (lines 21-25 above), so a consumer that treats
`:halted` as end-of-stream will silently drop the tail. This is now a note
on st-r6l9, along with the corollary from Open question 4 below: a
live-captured stream on a chart touching this seam must be compared against
a replayed one as a multiset or sorted-by-key, never byte order, and a
live-vs-replay round trip over an internal-send chart is a mechanical
detector for this bug.

### GAP 5 - `Statifier.start_session/2` deadlocks on an initialize-time `<invoke>` (st-xbaz)

**Title**: `Fixes start_session/2 deadlock on initialize-time invoke`

**Description**: Reproduced. `Statifier.start_session/2` calls
`DynamicSupervisor.start_child(Statifier.SessionSupervisor, spec)`.
`Session.start_link/2` runs `initialize/2` to quiescence inside `init/1`, and
the invoke pass runs at the end of that fold, so `start_child/5` calls
`Statifier.start_session/2` again - on the same `Statifier.SessionSupervisor`,
which is still blocked waiting for the parent's `init/1` to return. The run
hangs indefinitely with no output and no crash; a 120s timeout was needed to
kill it. The `catch :exit` in the private `start_session/3`
(`deps/statifier/lib/statifier/session.ex:1017`) only covers the "supervisor
not started" exit, not this one.

Workaround used for this spike: start the parent with a bare
`Statifier.Session.start_link/2` (unsupervised, ADR-0027 decision 2 sanctions
it) while `Statifier.Supervisor` is running, so the child's `start_child`
reaches an idle `SessionSupervisor`. With that, the whole invoke lifecycle
traced cleanly.

**Why the UI needs it**: the Livebook inspector will place sessions under the
library's own supervisor, which is the documented path. A hang with no error
message is the worst failure mode a notebook cell can have, and the
workaround (never use the supervised entry point for documents with
`<invoke>`) is not one a UI can reasonably impose on its user's SCXML.

### GAP 6 - No session-start effect, and no effect replay for a late subscriber (st-uqo4)

**Title**: `Lets a late subscriber see the trace it missed`

**Description**: Two halves of one problem. (a) `start_link/2` runs
`initialize/2` to quiescence before returning, so a pid added by
`subscribe/2` afterwards has already missed the initial `EntrySet`,
`ContentExecuted`, `InvokePass`, and `MacrostepStable`. Only `:subscribers`
at start avoids it, and that is not always available. (b) The stream opens
with a bare `Trace.EntrySet` at `macrostep: 1, round: 0`; there is no effect
naming the session, its `session_id`, or the document being traced, so a
consumer joining mid-stream has no self-describing header. `:record` /
`recording/1` (ADR-0029) records *inputs* - events, timer firings, cancels,
`interpret/2` batches - not the emitted effects, so it does not answer this
either.

**Why the UI needs it**: a Livebook cell is frequently evaluated after the
session exists, and a LiveView pane reconnects. ADR-0005's wire format needs
a self-describing opening message regardless, since a non-Elixir consumer has
no `%Machine{}` in hand to resolve indexes against.

### GAP 7 - Per-microstep configuration is not on the stream (st-ntf5)

**Title**: `Carries configuration on the microstep trace effects`

**Description**: Only `Trace.MacrostepStable`, `Trace.Done`, and
`Effect.BudgetExhausted` carry a `configuration`. A consumer wanting to
highlight the active configuration after each *microstep* must fold
`EntrySet`/`ExitSet` deltas onto the initial configuration itself, and get
`exitInterpreter`'s whole-configuration sweep and the parallel entry ordering
right while doing it.

**Why the UI needs it**: the diagram redraws per microstep when stepping, not
per macrostep. Folding is doable in Elixir against a `%Machine{}`, but
ADR-0005 commits to a wire format a statifier-rb or statifier-go consumer
could drive, and pushing configuration reconstruction onto every such
consumer duplicates engine logic outside the engine. A `configuration` field
on `EntrySet` (post-entry) and `ExitSet` (post-exit) would make each microstep
self-contained.

### GAP 8 - `InvokePass` and `CancelInvoke` report a phantom child for an unsupported `<invoke type>` (st-5fbw)

**Follow-up finding**, from the direction pass that ran the open questions
below - not one of the original seven.

**Title**: `Stops reporting InvokePass/CancelInvoke for an invoke that never started`

**Description**: `Statifier.Session.Target.supported_invoke_type?/1` accepts
only `nil`, `"scxml"`, and `http://www.w3.org/TR/scxml/`; anything else plans
`{:raise, :platform, "error.execution", {:invoke, ...}, []}` instead of
`{:start_child, ...}` at
`deps/statifier/lib/statifier/session/effects.ex:206-217`. Observed with
`type="http://example.com/not-scxml"`: `%Effect.Invoke{invoke_id: "vm1",
type: "http://example.com/not-scxml", ...}` is notified, so the UI does see
the attempt with the authored type, then `error.execution` is dequeued from
`:internal` with a full `Event.Cause` naming the invoke node. No child
starts, and because the type check precedes `start_child` this runs at
initialize with no supervisor and no st-xbaz hang. But `Trace.InvokePass`
still reported `invoke_ids: ["vm1"]`, and `Effect.CancelInvoke{invoke_id:
"vm1"}` was emitted on exit - so the core reports as started, and later
cancels, an invocation that never existed.

**Why the UI needs it**: a session-tree pane keyed off `InvokePass` /
`CancelInvoke` alone would draw and later remove a phantom child for an
invoke that failed before ever starting one.

## Architecture documentation

- **ADR-0002 / statifier ADR-0012** hold up exactly as written: nothing here
  needed the engine changed to observe it, and the eight gaps above are all
  emission or lifecycle asks filed upstream, not patches from this repo.
- **ADR-0005** (language-neutral trace wire format) is the record most
  affected. Its envelope commitment of `(macrostep, round)` on every message
  is currently satisfiable only for the trace effects (GAP 1), and its
  premise that a consumer maps identities back to locations through Machine
  tables is confirmed working - `Machine.at/2`, `transition/2`, `content/2`,
  and `id_to_index` are the four calls a serializer needs. ADR-0005 already
  decided the manifest-vs-per-message question that Open question 1 below
  wrongly recorded as open; see that entry for the correction. One caveat
  for whoever drafts `docs/wire-format.md`: per ADR-0007's Consequences,
  `attribute_locations` lives on the Document layer, not the Machine, so a
  location table built from a `%Machine{}` alone cannot give cond-vs-event
  hover granularity (sui-qay) - the manifest spec must say which layer its
  location table is built from.
- **ADR-0007** (text-first): source locations carry byte offsets as well as
  line/column, which is more than a text-first pane needs and removes any
  need to re-parse for highlighting.
- **ADR-0010** (cross-repo tracker authority): the gaps above are filed.
  Each one changes files under statifier-ex, so each is an `st-` bead worked
  there, with a `mirrors: sui-t36.1` line on the `sui-` side.

## Open questions

A follow-up direction pass ran every question below against the vendored
engine and settled all but one. Each entry keeps its original wording as
the dated record of what was asked, followed by its resolution.

1. **Does the wire format serialize indexes or resolved nodes? NOT ACTUALLY
   OPEN - this was an error in the original write-up.** ADR-0005 already
   decides it: "Identities as the engine emits them - state indexes,
   `t_index`, `c_index`, `invokeid` - never resolved nodes, and never
   per-event source locations. Locations resolve through the definition
   message", and a stream opens with a definition message (working type
   `session.start`) carrying the identity tables the compiled Machine
   retains. Recording it as open conflated "not yet specified in
   `docs/wire-format.md`" with "not yet decided" - it was already decided.
   Supporting reasoning worth keeping: the non-Elixir consumer with no
   `%Machine{}` is exactly who `session.start` exists for; per-message
   resolution would re-send locations on every message and break the
   byte-comparable golden-trace conformance mechanism ADR-0005 relies on;
   ADR-0007's matched-pair rule is satisfied structurally, since
   `session.start` is emitted per session, so manifest and stream are one
   compile's pair by construction; and the manifest does not wait on the
   engine, because the producer is statifier-ui code at the subscription
   boundary holding the `%Machine{}` (`Machine.at/2`, `transition/2`,
   `content/2`, `id_to_index`, all four verified by this spike), so GAP 6
   / st-uqo4 is not a precondition for it. One genuine caveat survives and
   is recorded as a note for `docs/wire-format.md` rather than as an open
   question, and lives in the Architecture documentation section's ADR-0005
   entry above: `attribute_locations` lives on the Document layer, not the
   Machine (ADR-0007 Consequences), so a Machine-built location table
   cannot give cond-vs-event hover granularity (sui-qay) - the manifest
   spec must say which layer its location table is built from.
2. **Should a child session inherit `:trace` and `:subscribers`? STILL A
   DESIGN CALL** - and, per ADR-0010 rule 1, statifier-ex's to make, not
   this repo's. GAP 3 proposes it, but inheritance may be wrong for a deep
   invoke tree where an inspector wants to attach selectively - that part
   of the question is genuinely still open. What the follow-up pass adds is
   a recommendation, now recorded as a note on st-fd7n: yes, as an opt-in
   start option defaulting to off, inherited transitively, with st-fd7n's
   accessor kept rather than replaced. The deciding fact is one this spike
   already established: `start_link/2` runs `initialize/2` to quiescence
   before returning, and a child is started inside the parent's invoke
   pass, so by the time any accessor can name the child's pid, the child's
   `EntrySet` / `ContentExecuted` / `InvokePass` / `MacrostepStable` are
   already delivered. A post-hoc attach can never observe a child's
   initialize burst, so an accessor alone cannot be made equivalent to
   inheritance.
3. **Is GAP 4's reordering reachable on any success path? SETTLED: yes, and
   it is worse than the original GAP 4 write-up says.** Reproduced with
   `<send target="#_internal">` in an `<onentry>`, nothing failing
   anywhere, and trace effects were delivered after `{:halted, :done}`.
   Full reproduction, mechanism, and consequence are now in GAP 4 above and
   on st-r6l9.
4. **How does the trace behave across a `Statifier.Replay` run? SETTLED.**
   Identical on plain paths; on the re-entry paths (see GAP 4 / question 3)
   it yields the same effect multiset and terminal state but in the
   correctly ordered stream that live delivery does not produce. Evidence:
   with `trace: true, record: true`, a delayed-send chart (`<send
   delay="20ms">` to final) replayed byte-for-byte equal, 16 messages both
   sides, terminal configuration and all three counters equal, timer entry
   replayed at its recorded position. The internal-send chart from GAP 4
   gave 25 messages both sides, same multiset, equal terminal configuration
   and counters, but not an identical stream: replay produces the monotone
   `(macrostep, round)` order (the planned list order, since `replay.ex` has
   no-op clauses for `{:raise, ...}` and `{:deliver, ...}`) while live
   delivery is scrambled as GAP 4 shows. Consequences for the inspector:
   replay is trustworthy for a time-travel pane, and until st-r6l9 is fixed
   it is actually better ordered than the live stream; but any comparison of
   a live-captured stream against a replayed one must compare as a
   multiset or sorted-by-key, not byte order, on charts touching that seam.
   A live-vs-replay round trip over an internal-send chart is therefore a
   mechanical detector for st-r6l9. ADR-0034's MapSet-iteration cross-OTP
   caveat stands as the one recorded reproducibility risk; same BEAM gave
   the same result here.
5. **What does an `<invoke>` of a non-SCXML `type` emit? SETTLED.**
   `Statifier.Session.Target.supported_invoke_type?/1` accepts only `nil`,
   `"scxml"`, and `http://www.w3.org/TR/scxml/`; anything else plans an
   `error.execution` instead of starting a child, and does so at initialize
   with no supervisor and no st-xbaz hang. This also turned up a new bug,
   now GAP 8 / st-5fbw above: `InvokePass` and `CancelInvoke` report a
   phantom child for the invoke that never started.
6. **The `Statifier.Effect` moduledoc's "not yet produced" rows for
   `:send`/`:send_delayed`/`:cancel` are stale - SETTLED, and broader than
   first noted.** All three are confirmed producible: `%SendDelayed{}` in
   the original pass, and immediate `%Effect.Send{}` and `%Effect.Cancel{}`
   in the follow-up pass. Both `Send` and `Cancel` also lack `round`, and
   neither was in st-nbmj's original enumerated list; st-nbmj now has a note
   adding them (GAP 1 above). This remains documentation drift upstream,
   not a UI gap on its own, but the missing-`round` half of it is now
   folded into GAP 1's bead.
